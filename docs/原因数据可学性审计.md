# 现有原因数据可学性审计与投入决策

2026-10-03。**建议优先建设事件级仿真数据，不把主要投入放在现有月度数据的大规模调参。**
现有数据并非完全无信号：它有设施类别相关的原因分布。但目前可用输入提供的事件细节信号很弱，
尚不足以支持可靠的具体原因诊断。结论是对研发预算的探索性判断，不是证明标签随机或所有算法都不可能改善。
本轮只审计／实验，不改原CSV、线上模型、输入契约、M3 gold、规则阈值、案例或业务数据库。

## 1. 范围、来源与方法

来源仍为3份已入库的 Electric Sheep Africa vaccine-cold-chain CSV；发生冷热偏移且标签有效的
**16,192条设施月度记录／10类原因／15项现有输入**，447个给定ID组、48个月。
不是本系统的模拟订单，不是品牌药品效价／报废标签，也没有配对的事件时间线。
数据与原正式评估相同，已多次查看，因此本轮是**探索性诊断，不是新的未见独立测试**。

```bash
LOKY_MAX_CPU_COUNT=1 .venv/bin/python scripts/audit_cause_learnability.py --output data/processed/cause-audit-new
```

最终完整产物在 `data/processed/cause-learnability-20261003-final/`：
`protocol.json`、`report.json`、角色身份CSV、学习曲线CSV、边际／条件关联CSV、两幅图。
只允许新目录；参数、种子、类顺序、来源／代码SHA、每次子样本身份与实际迭代数均保存。
新增 `ml/learnability.py` 与独立CLI，训练仍复用原未拟合预处理工厂，填补／编码／缩放只fit审计训练角色。

执行 **180次学习曲线拟合＋240次训练标签负对照**：

- 三种模式各3次：随机／给定设施ID组隔离各75%训练池、25%诊断验证；时间模式为三个不重叠的末尾六个月验证块，训练仅取各块之前的月份。
- 10%／25%／50%／100%嵌套训练子集，随机／时间在过去训练池内分层抽样；分组模式抽完整组，不跨验证组。
- 固定探针：LR balanced、原HGB balanced、HGB natural、禁用早停的HGB150轮、200树ExtraTrees容量探针。不是网格搜索，不按验证成绩推广某模型。
- 六种训练侧基线：全局原因先验、按先验随机排序、均匀随机、设施类别先验、类别平衡设施先验、设施类别随机先验。Top-3稳定排序或不放回随机排名，不用one-hot概率任意补两个并列类别。
- 每模式首个划分，原HGB balanced／natural，各做20次全局和20次设施类别内训练标签打乱；验证标签保持原样。没有修改原标签。
- 15特征全局及设施类别条件MI，各99次负对照；另检查3项未入模型的人员／疫苗上下文，只做描述关联、不作为已获准在线特征。

初次探索只用全局基线，预算标记为“先有界复核”；发现设施类别先验和默认早停混淆后，
最终审计增加对应控制，记录这一适应性探索，不包装成预注册的盲独立验证。
随机／分组重复间有重叠，时间验证块人群不同；均值和SD不是置信区间。
行／组／时间相关性未证明可交换，置乱尾部比例及BH运算是探索性参考，不能当作临床显著性证明。

## 2. 数据本身能说明什么

### 冲突不是整体低分的主解释

15项输入无缺测，`heat_sensitive`在本队列恒定；`monitoring_type`在每种设施类别内恒定，
在这份数据中是设施类别的别名，而非独立的监测证据。

完整15特征有16,158种输入画像，其中16,124种只出现一次，占 **99.5800%** 的记录。
31种画像各出现两个不同标签，涉及62行；在本次样本上，确定性映射至少错31行，即 **0.19145%**。
这是观测到的冲突，不是总体Bayes误差。大量单例尤其不能用“可记住99.8%”推断可泛化99.8%。
只保留context7时，3,035种画像多标签、11,827行在这些画像内；仅靠这7项背景并不能唯一确定原因。

有些语义共现值得说明：停电标签中21.10%上个月停电小时为0；无监测设备标签中29.29%字段报告有设备；
设备损坏标签中44.29%报告设备可用。字段时点、月度范围、设备身份与测量含义不明确，
**不把这些共现直接认定为错标签，不删除或“修正”原行来提高成绩**。

### 关联主要来自设施类别

设施类别单变量MI约占标签熵的 **4.12%**；监测类型相同，因为两者在本数据相互对应。
控制设施类别、扣除同类内置乱均值后，现有单变量最大额外MI仅约 **0.001134 nats**（设备类型），
其他项更小；条件BH参考值均未低于0.05。但这不是“证明所有联合信号不存在”。

额外检查 `has_epi_officer`、`cold_chain_staff_trained`、`requires_reconstitution`，
控制来源类别后最大剩余关联约 **0.000196 nats**，占标签熵 **0.00871%**。
这不支持只加这几列就能扭转成绩；也未证明它们早于真实事件可用。

## 3. 模型容量、学习曲线与先验基线

下表为本轮3次诊断验证均值，固定类顺序10类macro-F1；不是原五折正式表，也不是API当前模型成绩。

| 探针 | 随机：训练／验证 | 分组：训练／验证 | 时间：训练／验证 |
|---|---|---|---|
| LR balanced | 0.1446／0.1298 | 0.1449／0.1314 | 0.1446／0.1292 |
| HGB balanced（默认早停） | 0.2708／0.1243 | 0.2681／0.1319 | 0.3526／0.1342 |
| HGB natural | 0.1715／0.1152 | 0.1730／0.1167 | 0.2770／0.1167 |
| HGB balanced固定150轮 | 0.4809／0.1292 | 0.4869／0.1425 | 0.4978／0.1382 |
| ExtraTrees容量探针 | 0.9985／0.1197 | 0.9983／0.1216 | 0.9980／0.1219 |

大容量模型能记忆训练记录，却没有相应验证收益，不支持“模型根本没有拟合能力”的解释。
也不证明提升在数学上不可能，只说明本轮探针未获得可用的泛化能力。

默认HGB会自动早停，例如首随机／分组balanced全训练池实际38／32轮，natural36／32轮。
小子集则跑150轮。不能只看训练曲线突然降低就说“多加数据有害”；固定150轮复核后仍弱。
固定预算HGB从25%到100%训练池，验证macro-F1变化分别 **−0.00135／+0.01185／+0.00780**，
改善小且不一致，未显示单纯扩充同分布月度记录即可明显解决问题。

只用设施类别计数的先验，在随机／分组／时间的Top-1为 **22.22%／22.13%／22.31%**，
Top-3为 **52.45%／53.14%／52.91%**；HGB balanced相应Top-1 **17.50%／18.27%／17.63%**。
不能说所有复杂模型都比“设施类别常见原因”更有效。
先验macro-F1较低（约0.09），HGBbalanced能覆盖更多类别，这说明目标之间存在取舍，不是原验证集选模型方法必然错误。
自然类别权重提高Top-1但降低macro-F1；这不是全面性能提升。

## 4. 保留设施先验后打乱标签的结果

每行只使用该模式第一个划分，20次对照均值；不同于§3三次均值。

| 模式／HGB | 真实macro-F1 | 全局打乱均值 | 同设施类别内打乱均值 |
|---|---:|---:|---:|
| 随机／balanced | 0.12454 | 0.09481 | 0.13015 |
| 分组／balanced | 0.13055 | 0.09259 | 0.13360 |
| 时间／balanced | 0.13680 | 0.09651 | 0.13728 |
| 随机／natural | 0.11440 | 0.04845 | 0.11427 |
| 分组／natural | 0.11585 | 0.04876 | 0.11183 |
| 时间／natural | 0.12385 | 0.08742 | 0.12873 |

全局打乱变差：确有可学习关联。保留三类设施的标签比例、破坏类内记录与标签配对后，成绩几乎不变。
**最合理的当前解释是主要学到设施类别相关的原因先验，额外具体事件信息有限**；
不是证明生成器随机分配标签，也不是确认实际事件原因。20次置乱分辨率有限，不作新显著性检验或总体界限声明。

## 5. 投入决策与下一步

预算规则在代码中固定，属于工程资源分配参考，不是医药安全阈值：
各模式最优探索探针对最强基线的macro-F1增益都小于0.03，容量模型训练／验证差距大于0.30，
固定预算HGB从25%到全量的增益小于0.02。实际增益为随机 **0.01558**、分组 **0.02674**、时间 **0.01771**；
同时结合条件关联、来源内置乱与输入粒度判断，优先级为 `event_level_simulation_data_first`。

建议：

1. 保留现有来源为独立的历史合成基准与失败案例，不改其标签、不替换历史正式报告，也不把它升级成可靠事件根因模型。
2. 现有数据至多做小预算正则／权重／算法对照，明确macro-F1与Top-1取舍；本轮不推荐先投入大网格、深度网络或只加同分布记录。
3. 下一步先制定**事件级仿真数据规范**：同一event_id下的温度区间、开门／断电／设备状态时间线、路程时间及观测时点，与潜在扰动机理配对。
4. 标签来自未暴露给模型的潜在机理，不由现有M3判定或观察字段简单if/else反推；加入相近表现、背景变化、缺测、噪声、多原因／不确定情况，防止把cause_id、场景名或生成参数当特征。
5. 留出不同设施、种子、机理参数与场景组合；先与类别先验、简单事件特征模型比较，再决定更复杂算法。该成绩仅说明仿真机制识别，不证明真实业务／药品效价或因果有效性。
6. 不新增每单货量或仓库余额要求；原4产品、五仓库可停靠／医院禁日终停车及规则／审核执行依据保持原状。

本轮只完成审计与决策，**没有自动开始建设新训练集或推广新模型**，也不把私有人工审核或M6盲标材料用作ML金标准。

# 事件级故障机理仿真数据 v1

2026-10-03。根据 [可学性审计](原因数据可学性审计.md) 建设独立事件级数据，而非继续拼接设施月度记录。
已生成 **6,000个事件、5,626个事件家庭**，配套同一事件的温度、开门、电源、设备与路程进度观测。
本轮只建设数据和验证工具，**没有训练／替换线上M4模型，没有宣称新模型准确率或真实业务有效性**。

## 1. 标签到底表示什么

标签表示在观测窗口内，模拟器确实施加的**隐藏故障／扰动机理**，不是：
已调查确认的真实原因、对超温结果的唯一因果归因、药品效价、报废／放行标签或人工gold。
备电可能缓解停电，设备故障可能在观测截止前尚未产生明显温变；正常标签也允许背景开门、短暂供电波动和测量丢包。
**无注入故障不等于药品安全，有注入故障不等于超温／报废**。不按温度阈值、MKT或M3输出反造标签，也不筛到“必然超限”才接纳事件。

已知机理借用旧基准的10个代码，但这是新的事件级任务，不能混写成旧 `excursion_cause` 指标：

| 隐藏机理代码 | 本生成器的工程含义 |
|---|---|
| power_outage | 持续或间歇主电源中断；备电可运行 |
| generator_fuel_stockout | 主电源中断且备用燃料耗尽；指令与运行观测可能不一致 |
| equipment_breakdown | 冷却效率下降／失效，影响实际电流与热交换 |
| thermostat_failure | 控制目标偏移，可能导致偏热或偏冷 |
| door_left_open | 非计划的持续／间歇开门与环境换热 |
| staff_error | 操作机理子型：开门、设定点或热缓冲处理；不声称能从观测识别人员意图 |
| transport_delay | 路程进度滞后、暴露时间／环境换热变化 |
| ice_pack_not_conditioned | 抽象热缓冲温度偏移，可偏冷或偏热，不是实际冰袋配置指导 |
| overloading | 抽象气流／热分布受阻；不使用货物数量、重量或仓库余额 |
| no_monitoring_device | 温度获取显著缺失；本身不是实际温度偏移的证明 |

另有未映射的环境热扰动／传感偏差，统一监督标签为 `unmodeled_disturbance`；
这两类也存在于训练角色，不能将其称为“已经验证所有未见故障的开放集识别”。
多机理保存完整集合，`single_class_target=null`，不按温度最大值或注入强度伪造唯一主因。

## 2. 一个事件如何产生

1. 先采样背景虚拟设备、4产品之一、计划时长、观测截止、激励时序和隐藏机理参数。
2. 共用一分钟步进的冷却／环境／开门换热、热缓冲和产品滞后模型，先形成相互对应的状态。
3. 每5分钟取带噪测量，加入校准偏差、传感误报码、随机丢包与背景日志中断；只公开观测截止之前的数据。
4. 以公开观测前缀独立提取33项允许输入；标签只查隐藏施加时序，不查温度判定结果。

热交换系数、控制器、传感器误差与缓冲参数均为**工程演示假设**，没有厂家／实车标定。
同一代码不是对应固定温度模板：背景、极性、持续时间、设备响应、缺测和其他机理会改变观测。
不同代码也可能产生相同或相似表现，尤其人员操作和设备／门状态的关系。

观测记录每个区间明确为 `[start_min,end_min)`，带噪采样值在该区间按常值使用，
能转换为原M2 `TemperatureSeries`；这不等于重建了真实连续峰值。
MKT仍用项目已有的时间加权方法与83.144kJ/mol演示假设，缺测时仅报known-only值和覆盖率。
完全未知的温度／均值／超限时长／MKT保持null，不填0或伪称安全。
本默认批次有部分原始通道缺测，但每个事件仍有至少一段已知温度，摘要特征的null计数为0；全缺测路径另有专项测试。

## 3. 相同观测、不同原因的明确挑战

374对事件使用相同背景、驱动、过程／观测随机流，只将“门未关”与“操作失误的开门子型”换成不同隐藏语义。
它们除event_id外的公开观测完全相同、33项特征完全相同，但隐藏目标不同。
两成员一起留在同一角色，均标 `observationally_ambiguous=true`；ID和歧义标志都不得作为输入。
**这个标志为false不代表其他事件一定能唯一诊断**。
未来应报告这些事件的候选集合／拒判覆盖，不能丢掉它们后声称整体准确率高。

## 4. 六类角色，而不是只随机切一张表

| 角色 | 行数 | 背景与留出政策 |
|---|---:|---|
| train | 3,000 | 32个基础虚拟设备、pulse／sustained／intermittent、nominal参数 |
| validation | 600 | 同基础设备及参数分布，新独立事件家庭，用于以后调参 |
| test_iid | 600 | 同分布独立事件，用于冻结后的诊断评价 |
| test_facility | 600 | 8个与其余角色不重叠的虚拟设备，同机理／时序范围 |
| test_scenario | 600 | ramp／two_pulses两种未见激励时序，与其他角色不重叠；不是未见原因类别 |
| test_parameter | 600 | 不同背景环境、传感噪声与丢包参数范围；不是所有观测值都不重叠 |

虚拟设备不复用真实医院／仓库身份，也没有真实GPS或订单关联。
基础环境参数18–35°C、噪声0.08–0.35°C、丢包0.015–0.08；参数留出背景40–48°C、噪声0.6–1.2°C、丢包0.15–0.30。
实际观测还受机理和噪声影响，因此两种角色的测量值可以重叠。
普通验证／IID角色共享设备是有意的，不称为跨设备验证；各测试角色应分开报告，不能混池掩盖分布偏移。
事件家庭、事件ID、家庭过程种子不跨角色；完全相同的特征画像若跨角色，生成器报错，不重采样直到“好看”。

## 5. 文件与模型输入隔离

```text
event-simulation-20261003/
├── manifest.json             配置、定义、分割审计、来源／文件SHA
└── train|validation|test_*/
    ├── observations.jsonl    同一event_id的公开测量前缀
    ├── features.csv          只有33项允许的预测器；无ID或标签
    ├── index.csv             行序与event／family／asset／role映射，不是输入
    └── labels.private.jsonl  注入机理、标签集合和隐藏计划，不是输入
```

允许输入：产品类别、已知计划／观测时长、覆盖率，温度相对区间、变化率、冷热已知时长／缺口、known-only MKT，
环境、开门、电源／备用指令与运行、燃料、电流、冷却指令、设定点、气流、温差、湿度、进度滞后，以及观测到的共同变化。
这些是**带噪观测或其统计量**，不是 `fault_active`、真实效率或机理参数。
`extract_features()` 不接受隐藏plan／label字段；`read_predictors()` 只打开特征文件、严格核对列顺序，不读取标签或元数据。
禁止event／family／asset ID、角色、场景名、时序模板、种子、机理码、严重度、生成参数和歧义标志入模型。

`private`仅表示与预测输入分开，不是密码保护，也不是独立人工评审。
以后监督学习只连接**train**标签；验证可用于选择，测试成绩不得用来调生成器或选模型。
不悄悄删除multi／unknown／no_fault／ambiguous或未来尚未发生的故障以缩小评价分母。
旧M4输入契约仍是运输13项／设施月度15项，**不能把新33项直接送入旧模型**；未来需单独版本化模型与API。

## 6. 生成和只读校验

```bash
LOKY_MAX_CPU_COUNT=1 .venv/bin/python scripts/generate_event_dataset.py \
  --events 6000 --seed 42 --output data/processed/event-simulation-new
LOKY_MAX_CPU_COUNT=1 .venv/bin/python scripts/verify_event_dataset.py \
  --dataset data/processed/event-simulation-new \
  --report data/processed/event-simulation-new-validation.json --replay-per-role 20
```

仅允许新目录／新报告，数据和报告是可再生成产物，不入Git；代码和规范入Git。
固定版本、seed、事件数可复现每份数据文件SHA；manifest创建时间不同，因此不承诺整个目录manifest逐字节一样。
规模范围120–50,000；小冒烟批次不保证每角色覆盖所有类，6,000默认批次各角色均覆盖全部10类已知机理。
没有下载新第三方数据，没有读取／改写私有人工标注、旧案例或旧ML数据。

## 7. 本轮实际结果

路径 `data/processed/event-simulation-20261003/`，24份数据文件约 **114.6MB**；6,000行、5,626家庭。
实际标签：single **3,855**、multi **692**、unknown **547**、no_fault **906**，其中single包含748条显式歧义对成员。
标签比例是设计覆盖，不是真实业务患病／失效率。计划机理可能在截止后才启动，正确变为当前no_fault／较少机理，
所以实际比例不强行等于生成模式概率。
基础／设备／时序留出温度覆盖均值约0.888–0.896，参数留出约 **0.7264**；保留缺测，不假定完整日志。

只读验证 **passed**：全6,000行事件／特征／标签／索引一致、M2区间契约通过，
120次确定性重放、120次只改变未来机理的前缀不变检查、374对歧义观测相等检查通过；
事件家庭／设备／时序留出重叠0，跨角色完全相同特征画像0，全部文件SHA核验。
这些是生成器一致性和结构检查，**不是独立领域真实性验证或模型准确率**。
79项专项通过；独占测试图谱完整回归 **750 passed／0 skipped／6 warnings**（既有SWIG和SHAP／Matplotlib提示）。
最终校验报告 `data/processed/event-simulation-20261003-validation-final.json`，含校验代码SHA；
manifest SHA为 `8064816f90574cbfb0ccfc48a24203e3d3195dcae7b96013c5189183e52f1dd9`。
生成源SHA与当前源代码／产品配置一致，原案例SQL／JSONL、两个线上模型与元数据SHA不变。
测试容器独占新建后清理，用户本机demo继续健康运行。代码、规范、测试按约定本地commit，不push；生成物不入Git。

本轮没有模型分数，没有自动接入运行系统，不改4产品、五仓库停车约束、真实数量库存边界或人工审核依据。

后续更新：上述基线／冻结分角色评估已完成，见 [事件级模型基线评估](事件级模型基线评估.md)。

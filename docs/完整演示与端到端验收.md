# 完整演示与端到端验收

## 范围与固定输入

业务订单始终为模拟数据，不接真实医院订单、GPS 或交通。固定演示日 `2026-10-01`、seed `41`，
普通主链使用 4 单疫苗、主仓货源、480 分钟收货窗和 3 辆演示车；允许终点只选 Northpoint／Hougang。
高级参数中的货量只是旧规划模型输入，不是业务货量管理；独立加急不输入数量，次日自动假设模型供货。

验收分两层，不能把 ASGI 测试冒充真实浏览器测试：

| 场景 | API 全链断言 | 浏览器主链 |
|---|---|---|
| 普通生成、预览、建单 | 同种子完整配置／来源哈希复现，预览只读，计划可行 | 表单生成、复核约束、确认并自动发车 |
| 独立加急 | 同作业、无货量输入、候选／执行一致、采纳重试幂等 | 比较、选择、采用，地图共享状态 |
| 温控异常及补送 | 关联原作业／订单／发生地，原判定重试，实际送达才能结案 | `+` 登记、详情内联比较、补送、签收备注结案 |
| 机械故障 | 故障车冻结，原单保持 failed，备用车替代单实际交付；无虚构转运 | 独立 API 场景，不强行并入故障车停车主链 |
| 延误巡检与重排 | 固定三站路径，人工模拟额外延误 30 分钟，迟到 1 → 0，过时方案拒绝、接受幂等 | 独立 API 场景 |
| 收工停车、次日 | 收尾完毕才能确认，真实位移，停妥才建次日，继承车位、重置日里程、不复制临时任务 | 可见控件预览／确认／下一日 |
| 多货源／运力不足 | 保留全部配送组、保留未服务订单，明确不可行 | 由既有生成器 UI 和前端数据测试覆盖 |
| 图谱与离线 | `--graph` 真实 why／audit 及发生地、目的地证据 | 真实问答，离线入口无执行按钮 |

## 一条命令重跑接口验收

```bash
.venv/bin/python scripts/run_demo_acceptance.py
.venv/bin/python -m pytest -q tests/test_demo_acceptance.py
```

默认创建新的临时目录；保存 SQLite、案例 JSONL 和 `report.json`（含检查列表、完整输入及各阶段快照）。
指定 `--output /absolute/new-directory` 时目录必须不存在，拒绝覆盖历史验收证据。失败返回 1 并保留部分数据库。
重复两次会比较源批次和延误候选，不比较包含真实创建时间／独立 UUID 的案例 ID。

只控制运输模块的测试墙上时间，每次真实 tick 最多推进 30 秒墙上时间（300×＝150 模拟分钟）；
所有订单、候选采纳、交付、停车及次日状态都由真实接口／状态机提交。
**不改 SQL 中的配送状态、不注入人为站序、不绕过停车完成条件。**
默认图谱写入返回 False，明确标为 `graph_mode=not_verified`，不是模拟一次成功同步。

已有初始化完毕的**独立测试图谱**时：

```bash
NEO4J_URI=bolt://127.0.0.1:17687 NEO4J_PASSWORD=acceptance-demo \
  .venv/bin/python scripts/run_demo_acceptance.py --graph
```

此模式会写入模拟案例并验证真实图谱问答，不应用于不允许写测试案例的业务图谱。

## 浏览器复跑

先启动新目录里的 API，防止覆盖本项目现有运行数据：

```bash
DEMO_CHECK_DIR=$(mktemp -d)
DATABASE_URL="$DEMO_CHECK_DIR/browser.sqlite3" CASE_RUNS_FILE="$DEMO_CHECK_DIR/runs.jsonl" \
  KG_SYNC_ENABLED=1 .venv/bin/python -m uvicorn --app-dir src api.main:app --port 18000
# 另一终端：
pnpm --dir frontend-vue dev --host 127.0.0.1 --port 15173
```

上述 API 的 `NEO4J_*` 应指向已经初始化的独立测试库。打开
`http://127.0.0.1:15173/?api=http://127.0.0.1:18000`，使用 Playwright CLI：

```bash
mkdir -p output/playwright
playwright-cli -s=pharma-demo open 'http://127.0.0.1:15173/?api=http://127.0.0.1:18000'
playwright-cli -s=pharma-demo snapshot
playwright-cli -s=pharma-demo run-code --filename scripts/browser_demo_acceptance.cjs
playwright-cli -s=pharma-demo close
```

脚本仅点击／填写可见控件，观察实际 HTTP 响应；不 mock 返回值，不改 Pinia 状态。
确认按钮本来就会自动发车，脚本随即在运输视图按「暂停」，处理加急／异常后再按 300×，避免操作期间订单已送完。
每次重跑必须使用新的空库；失败证据保留，不用清库方式重试。成功输出 JSON 检查列表并生成完整页面截图。
浏览器记录与截图位于被 gitignore 排除的 `output/playwright/`、`.playwright-cli/`。

## 讲解顺序（约 5–8 分钟）

1. 声明业务数据为模拟，展示日期／seed／原始订单与来源快照。
2. 五仓停靠选择器，强调医院不是当天终点，查看路线与不可行原因。
3. 确认发车后暂停；添加不带货量的加急，展示候选影响与地图更新。
4. 登记关联订单的温控异常，分别展示发生地点和收货医院；采用补送方案。
5. 推进时钟直到真实补送交付，填写备注结案；问答展示该案例的法规／SOP／设施证据。
6. 收尾行驶完毕后确认停车，停妥才建立次日；展示车位继承和临时订单不复制。
7. 用验收报告展示故障／延误／资源不足的独立场景，最后演示离线沙箱。

故障场景不假定车对车汇合、拖车或维修能力；PDPTW 在途救援／重排仍明确拒绝。

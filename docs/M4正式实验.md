本页是有来源、可复跑的人工整理摘要，非自动导出的全部中间数据；运行数据、折模型、PNG、NPZ 和长 JSON 不入 Git。
本轮完成正式多折、可用的分组／月份验证、校准、特征消融、失败分析和对应模型 SHAP，**没有推广或替换线上模型**。

后续的 [原因数据可学性审计](原因数据可学性审计.md) 进一步检查训练／验证曲线、设施类别先验、
固定预算容量及打乱训练标签的负对照，建议优先补事件级仿真信息。它是对同一已评估队列的探索诊断，
不替换本报告的正式协议／指标，不将单变量弱信号或低分解释为已经证明标签随机。

## 1. 任务与数据边界

| 任务 | 数据与样本 | 输入 | 评价对象 |
|---|---|---|---|
| risk | 8,000 条运输；失效 1,574、非失效 6,426 | 13 个可解释运输摘要 | 无时间戳的运输级失效分类 |
| cause | 三类设施文件筛出 16,192 条偏移月度记录；10 类原因 | 既有 15 特征，另做 7 特征消融 | 已发生偏移月度队列的候选原因关联 |

风险疑似合成，原因明确为仿真；源、许可证和粒度见 [数据字典](../data/ml/DATA_DICTIONARY.md)。
两任务不代表品牌药品效价／报废标签、真实根因、在线传感器、未来 30／60 分钟预警或实际运营效果。
风险 395 条存在缺值，不符合完整线上输入契约；离线训练按**本折 fit 集**中位数填补，不表示 API 开始接受缺测输入。
原因全量 16,192 条符合既有输入契约，但没有事件发生时刻，不能证明所有月度字段在事件前可用。

原因分组键为 `facility_level:facility_id`，共 **447** 个给定 ID 组；月份为 2021–2024，共 **48** 个。
同设施／月／疫苗键有 **642** 条重复行，完整 15 特征有 **34** 条重复预测输入。
447 个组内设备类型都有多种取值；因此设施划分仅称“给定 ID 的稳健性检查”，不声称验证了真实机构泛化。
不自动删除重复预测输入：相同上下文可能对应不同原因，逐折记录训练侧／测试侧重合输入及域外特征计数。

## 2. 防泄漏与实验协议

- 风险：完整数据 **5 折分层随机外层验证**。没有时间戳／设施标识，不编造时间或机构划分。
- 原因：**随机 5 折、设施组不重合 5 折、月份前推 5 折**；每种分别跑 full15／context7，共 30 个原因折次。
- 每个外层训练池再分为 fit／calibration／selection 约 60／20／20；分组按组、时间按整月，不保证行数正好该比例。
- fit 只拟合预处理和候选分类器；calibration 只拟合校准映射；selection 选分类器、校准方法及风险 F1 阈值。
- 外层 test 只做最后评分，不选择模型、阈值或校准。随机与分组四角色不重合；时间严格 `fit < calibration < selection < test`。
- 模型选择：risk 以 selection PR-AUC，cause 以 selection macro-F1。校准选择：risk 最小 selection Brier，cause 最小 selection log loss。
- 预处理／类别编码只 fit 当前 fit 集；样本权重只由 fit 标签计算。校准**不加平衡权重**，保留校准队列自然频率。
- 固定 seed=42，内层 seed=42+折号；模型 seed=42。输出完整角色 CSV、样本身份、来源／代码／分区指纹与依赖版本。
- 对每个固定候选也报告外层 raw 分数；比较表用于实验总结，不用测试分数反过来挑当前折模型。

与 [scikit-learn 分组验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)、
[独立校准数据说明](https://scikit-learn.org/stable/modules/calibration.html) 对齐。
组、月份和标识不是共同订单 ID，不跨运输与设施数据捏造关联。

候选为 LR 与 HistGradientBoosting；risk 还检查 LightGBM／XGBoost。
本机两者分别因 OSError／XGBoostError 不可加载，记录 unavailable，**未冒称训练完成**，未修改全局 OpenMP 环境。
因而本轮的可执行算法正式比较是 LR／HistGradientBoosting＋经验先验／多数类基线。

## 3. 完整实测结果

下表为各外层测试折的**均值 ± 样本标准差**。SD 不是置信区间，折次有重叠训练池，不能拿它作独立显著性证明。
风险 fit 只有约 48% 全量数据，协议与部署版 70／15／15 单次切分不同，不把两组 F1 差异称为部署提升／退化。

### 3.1 风险（二分类）

| 指标 | 五折结果 |
|---|---:|
| F1（本折 selection 所选阈值） | **0.6635 ± 0.0179** |
| ROC-AUC | **0.9045 ± 0.0092** |
| PR-AUC | **0.7087 ± 0.0296** |
| Brier：同一基础模型 raw → 校准 | **0.1091 → 0.0933** |
| Log loss：raw → 校准 | **0.3398 → 0.2961** |

五折都在内层选中 HistGradientBoosting＋sigmoid。比较 none／sigmoid／isotonic，不按外层 test 挑最好方法。
多数类／经验先验基线：F1=0、AUC=0.5、PR-AUC≈0.1968、Brier≈0.1580。
Brier、log loss 还包含区分能力等因素，不单凭它们宣称校准完成；同时保存 ECE-10 与带样本数的可靠性箱数据（可由 OOF 数组复算）。
指标只针对这份疑似合成运输基准，不等于真实药品风险概率。

### 3.2 原因（10 类，校准保留预测类别顺序）

| 特征与划分 | 测试覆盖行 | macro-F1 | Top-1 | Top-3 | Brier raw → 校准 |
|---|---:|---:|---:|---:|---:|
| full15 · 随机 | 16,192 | 0.1322 ± 0.0091 | 0.1713 ± 0.0240 | 0.4537 ± 0.0267 | 0.8926 → 0.8864 |
| context7 · 随机 | 16,192 | 0.1310 ± 0.0036 | 0.1496 ± 0.0046 | 0.4279 ± 0.0063 | 0.9032 → 0.8908 |
| full15 · 给定设施 ID | 16,192 | 0.1308 ± 0.0026 | 0.1500 ± 0.0030 | 0.4345 ± 0.0029 | 0.9055 → 0.8902 |
| context7 · 给定设施 ID | 16,192 | 0.1358 ± 0.0062 | 0.1618 ± 0.0151 | 0.4417 ± 0.0224 | 0.8996 → 0.8891 |
| full15 · 月份前推 | 14,520 | 0.1259 ± 0.0086 | 0.1497 ± 0.0051 | 0.4174 ± 0.0212 | 0.9458 → 0.8913 |
| context7 · 月份前推 | 14,520 | 0.1314 ± 0.0056 | 0.1588 ± 0.0180 | 0.4271 ± 0.0356 | 0.9038 → 0.8892 |

前推验证不评早期 1,672 行预热数据，不能与全体随机 OOF 直接作等人群比较。
所有原因折次内层选择 temperature scaling；它改变概率置信度，但不改变 argmax／类别排序，因此**不提升 Top-1、Top-3 或 macro-F1**。
随机 full15 的多数类基线 Top-1≈0.1607、Top-3≈0.4201、macro-F1≈0.0277。
full15 设施／时间 Top-1 甚至低于相应多数类基线，不能宣传成可靠根因诊断。

## 4. 特征正当性与失败分析

context7：设施层级、区域类型、设备类型、设备年龄、疫苗名称、冻敏与热敏。
它排除设备功能、备用电源、停电小时、监测／日志字段与年月，作为较少依赖同月动态观察的敏感性对照，
**仍不证明这些字段真实早于某个事件**。full15 与 context7 所有列保持同一外层划分，比较不是重抽样后碰巧更优。
禁止把原因标签、偏移检测结果、极值、VVM／shake test、报废／浪费结果和数量混进特征以“提高准确率”。
`feature_manifest` 列出字段、可用性限制与禁用列；每折审计同时列出新类别、数值超出 fit 范围的测试计数。
离线评分包含域移，不意味着线上域外拒绝机制被取消。

风险 OOF：**360 假阴性、871 假阳性**；>7 天运输段错误率 31.75%，1–3 天段 4.61%。
这只是固定诊断分箱中的关联，不把天数设为新的临床阈值。
缺值行错误率 16.46%，完整行 15.33%；无传感器间隙只有 3 行，不能从该小组得出总体结论。

原因 full15 随机最常见误判包括：

- `no_monitoring_device → ice_pack_not_conditioned`：909 条。
- `transport_delay → ice_pack_not_conditioned`：643 条。
- `power_outage → ice_pack_not_conditioned`：435 条。

原因任务只有月度上下文，没有实际开门时点、冰袋处理过程、设备故障调查等事件证据。
前置上下文不能唯一确定已发生的具体原因；弱性能、合成标签机制与队列筛选都须披露。
每个协议输出各类支持数／精确率／召回率／F1、混淆矩阵、分组错误率及高置信错误样本，样本仅在评分后用于诊断，
不用于改阈值、选模型或偷偷纠正标签。

## 5. SHAP 与在线解释的对应关系

四份独立解释：当前部署 risk／cause、正式实验第一折 risk／cause。
部署模型分别核对原模型 SHA、原数据 SHA 和原 70／15／15 分区 SHA，背景取原训练区，解释取原留出区。
正式折模型是另一个模型／数据预算／校准协议，不把它的解释图贴成当前部署模型结果。

使用真实 [Kernel SHAP](https://shap.readthedocs.io/en/latest/generated/shap.KernelExplainer.html)：identity 链接、概率空间、每模型 12 个确定性留出样本，
12 个训练背景样本、128 次子集预算。仅取完整、符合既有输入契约的行；逐模型核验 `期望值 + 各特征 SHAP = 预测概率`，
本机残差在数值精度范围。保留全输出类别轴，不把多分类类别轴当成特征轴。
风险图聚合正类，原因图聚合样本与全部输出类；**小样本均值不是总体特征重要性**。
边际背景混合可能破坏温湿度／设备字段依赖，故不是物理干预或因果诊断。

旧 `reports/ml/shap_risk.png` 属历史模型实验；它不自动等于当前 13 特征部署模型的 SHAP。
线上仍是“单特征参考替换敏感性”，不保证加和，也不是 SHAP。此次正式 SHAP 是离线报告产物，没改变 API 返回口径。

# PharmaColdOps 前端与提案一致性核查

> 核查对象：`frontend-vue/`（Vue 3 + Vite + Pinia + Leaflet）对照 `proposal/PharmaColdOps-Proposal-EN.md`（已提交英文版）
> 核查方式：只读代码走查（read/grep/glob + PowerShell），所有判定均给出 `文件:行` 证据
> 核查日期：以工作区当前状态为准（`src/` 后端 API 已完整实现，非占位）

## 〇、父代理复核补充（2026-09-27，直接调用真实 API 实测）

本报告的两条关键发现已由父代理独立复核，结论**成立**，并补充实测数据与两处口径更正：

1. **`/api/route` 无 UI 入口——成立。** 复核：`grep fetchRoute` 在 `frontend-vue/src` 只命中定义（`decisions.js:136`）与导出（`:200`），22 个 `.vue` 组件中**零命中**；`routeResults` 同样只有定义。实测后端该端点**功能正常**：本机 uvicorn 下 `POST /api/route {run_id:"R20260918-022350-635"}` 返回 `order_id=RO-R20260918-022350-635`、`total_distance≈28.82 km`、1 车、`on_time_rate=1.0`、0 违规、0 未服务，含 GeoJSON。→ **措辞更正**：本报告 §一-1 末句把这写成「提案 Figure 4 说明文字在 UI 层面不成立」；准确说法是「**后端为真、界面未接线**」——提案提交件（EN §1）的原句是 "the frontend calls the live routing and graph QA endpoints for archived reshipment cases"，我方**提交后修订的源稿**已把说法改为「经调度链路把结案案例提交进实时作业」，与代码现状一致；演示时路线应从调度链路展示（见 `proposal/提案-PPT-前端一致性核查.md` §3.1 T1）。
2. **离线模式沙盒不可达——成立，但有一个前提条件要写清。** 复核：`IncidentList.vue:48,52` 确认事件卡按钮仅在 `decisions.useApi` 为真时渲染，离线时该列表只显示「离线无归档」提示。→ **补充**：未结案时也无归档，因此**必须"起后端 + 有一条已结案案例"**；本机 `data/audit/runs.jsonl` 现有 **18 条**归档，`GET /api/runs` 实测 `count=18`，点最上面那条即可打开沙盒。
3. 附带实测：无 Neo4j 时 `POST /api/qa` 返回 **503 "knowledge graph unavailable"**（与报告 §一-6 描述一致）；未知 `run_id` 的 `/api/qa`、`/api/route` 分别返回 422/404；`/api/health` 返回 `{"status":"ok","module":"rule_engine","products":[4 类]}`；OpenAPI 共 **25** 个端点。
4. 环境说明：父代理在 DSH 沙箱内启动 `vite dev` 失败（`spawn EPERM`，沙箱禁止子进程 spawn），属环境限制、非项目缺陷；**前端未能实际渲染验证**，本报告的 UI 结论均来自源码走查。

## 一、结论摘要（按重要性排序）

**1. `/api/route` 在前端是死代码——提案"在线模式显示已结案案例的补发路线"缺少 UI 触发点。**
`frontend-vue/src/stores/decisions.js:136` 定义了 `fetchRoute(runId, algorithm)`，但全仓库**没有任何调用点**（`grep 'fetchRoute('` 仅命中第 136 行的定义本身，`routeResults` / `routePending` 同样只被定义与导出）。后端 `/api/route` 确实存在且严格只接受**已结案**的补发案例（`src/api/service.py:413-420`：`find_run` 找不到→404，`build_reshipment_order` 返回 None→422 "does not require reshipment"），但前端页面上**没有任何按钮、watcher 或事件**会发这个请求，也**没有任何面板**渲染它的返回值。地图上真正在跑的路线来自 `/api/dispatch/*`。提案 Figure 4 说明文字"`/api/route` solves the case's reshipment route"在 UI 层面不成立。

**2. 离线模式下"决策沙箱"完全打不开——演示时点不出来。**
`CaseDrawer`（唯一包含 `ExcursionInputs` / `ScenarioList` / `RuleConfig` / `ZonePlot` / `Timeline` / `EvidencePanel` / `RiskIndex` / `RuleList` / `RulePath` / `DecisionBanner` 的组件）只在 `overlay.caseOpen` 为真时渲染（`src/App.vue:68`）。而 `openCase()` 全仓库只有两个触发点：`IncidentList.vue:38` 点击"已结案事件卡"、`ReroutePanel.vue:57` 点击地图上的历史事件标记。离线时 `history.runs = []`（`stores/history.js:51-58`）、`incidentEvents = []`（`ReroutePanel.vue:40-50`），因此**打开 `http://localhost:5173` 只有地图 + 配送面板，判定沙箱、规则沙箱、证据面板全部不可达**。API 模式且数据库为空时同样打不开。

**3. "目的地/数量选择界面尚未构建"这一说法偏保守：目的地选择**已经**存在，缺的是数量与时间窗。**
提案 line 75 说 "a screen for choosing destinations and quantities remains to be built"。实际上`ExcursionInputs.vue:69-76` 已有"补发收货医院"下拉框（`L.center.destination`），选项来自新加坡路网 10 家医院（`stores/sandbox.js:16`），并通过 `eventPayload` 的 `destination_facility_id` 随请求上送（`lib/api.js:25`）。真正缺的是**数量**（由后端固定，`src/optimisation/daily_orders.py:43` 注释明确"One order's worth (30 units)"）与**时间窗**输入。

**4. 全仓库没有 vue-router、没有 `src/views/`、没有 `src/router/`——"每一页/每个视图"实际上不存在。**
`package.json` 依赖仅 `leaflet` / `pinia` / `vue`，无 `vue-router`。页面结构是**单页 + 三个 overlay 状态**（`stores/overlay.js`：`historyOpen` / `newInboundOpen` / `caseOpen`）。`frontend-vue/dist/` 的 30 个 hash 文件是 Vite 历次构建产物堆积，不是路由分块。

**5. 双语界面 CONFIRMED，且机制完整。** `i18n/index.js:23-45` 支持 `?lang=` > `localStorage` > `navigator.language` 三级优先级，`HeaderBar.vue:52-55` 有 EN / 中文 切换按钮，`setLocale` 会同步 `<html lang>`。`en.js` 413 行 / `zh.js` 403 行平行字典，无缺失键。

**6. 四状态 QA CONFIRMED（含拼写细节差异）。** 后端契约是 `ok` / `no_case` / `insufficient_evidence` / `unsupported`（`src/api/schemas.py:294`，`src/knowledge_graph/qa.py:45-49`），前端 `QAPanel.vue:51-64` 四种全部处理，本地化文案在 `i18n/en.js:221-223` 与 `zh.js:220-222`。提案 line 142 用自然语言写 "no case / insufficient evidence"，与代码里的下划线机器值 `no_case` / `insufficient_evidence` 不完全一致（API 契约以代码为准）。`db_error` 走 HTTP 503，前端 catch 分支会退回关键词回答并**不向用户提示 503**（`QAPanel.vue:65-68`）。

**7. 配送作业链路完整，且提案漏写了 5 个已在用的能力。** 规划（`/api/dispatch/plan`）、建作业（`/api/dispatch/runs`）、发车（`/depart`）、模拟时钟（`/tick` 1s 轮询 + `/speed`）、应急插入（`/api/dispatch/reshipments`）全部已接线；提案未提及的**夜间停靠规划**（`/api/dispatch/overnight-plan`）、**里程/车辆数/停靠数上限与终点站开放路线**、**未服务订单拒因**、**换批次（reroll seed）**、**运行回放**均已实现。

**8. 存在 4 处死代码 / 潜在缺陷，examiner 容易点到。** 详见 §五。

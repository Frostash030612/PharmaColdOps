# 57 场景金标准标注 · 分包与流程（A 协调 · v1）

> 对应 DAILY_PLAN：A 9/9 ③「规划 57 场景的标注分包」；下接 A 9/10 ①（发 rubric）、9/14（收稿+kappa）、9/18（出 `gold_labels.csv`）。
> 目标：用**独立人工双标注**替换 `data/scenarios/scenarios.csv` 的占位 `gold_label`，打破「引擎当自己答案」的反循环（提案 §8.3）。标注说明书见 [`docs/annotation_rubric_v1.md`](annotation_rubric_v1.md)。

## 1. 一句话方案

**B、C 两人各自独立标全部 57 个场景（S001–S057）**，互不讨论；A 收两份 → 算两人 Cohen's kappa → 仲裁分歧 → 9/18 产出 `data/scenarios/gold_labels.csv`（独立标注终版）替换占位 → 9/19 引擎 vs 金标准评估表。

> 说明：A 分工表里「B/C 各半」的措辞，按 B、C 各自 W0 栏（见下）落实为**双人各出一份全量**——只有同一批场景两人都标，kappa 才有交集可算（全部 57 条）。若想改为真"各半"，需另留重叠集供 kappa，且与两栏现有排期冲突，故不采用。

## 3. 独立性规则（防泄漏）

1. 只读 `annotation_rubric_v1.md` + 自己那份场景清单；**遮住/删掉** `gold_label` 列再标。
2. 不打开 `src/rule_engine/`、`tests/`、`src/api/`、demo 页面。
3. 两人**不讨论答案**，直到都交稿、A 公布分歧清单。
4. 不确定照 rubric 判，疑虑写 `note`（rubric §7）。

## 4. 交付物格式（回给 A）

- 三列：`scenario_id`、`disposition`（`release`/`quarantine`/`retest`/`scrap`）、`note`（可选，写疑虑）。
- 57 行，缺一不可；文件命名建议 `gold_label_<B|C>.csv`（可放自己本地，9/13 连同消息发 A；A 合并后入 `data/processed/`，不入库）。

## 5. A 侧流程（9/14–9/19）

| 日期 | A 动作 |
|---|---|
| 9/14 | 收 B/C 两份 → 算 **Cohen's kappa**（目标 ≥0.8）→ 出分歧清单，按分歧类型归类（规则理解歧义 / 阈值歧义 / 场景歧义）。 |
| 9/15–16 | 阈值落地（`vaccine_2_8`、`frozen_m20` → 9/15；`insulin_2_8` → 9/16）：**若阈值变，列出受影响场景，发 rubric v1.1 + 补标子集**给 B/C（限定在受改产品内），并要求限期补回。 |
| 9/17–18 | 处理第二批分歧 / 仲裁；生成 `data/scenarios/gold_labels.csv`（独立标注终版），替换占位 `gold_label`；场景库随阈值变化同步。 |
| 9/19 | 引擎 vs 金标准全量评估（准确率 / macro-F1 / 各类别召回，重点 scrap 与 quarantine / 覆盖率 / kappa）→ `data/processed/` 评估表 v1。 |

## 6. 风险与对策

- **两人答案高度一致但仍可能"系统性同错"**（例如都误解某条规则）：kappa 高不代表对——A 仲裁分歧 + 与 rubric 意图逐条比对兜底；报告如实写"独立双标注 + A 仲裁"，不吹成"真值"。
- **阈值 9/15–16 才落地，晚于标注**：靠 rubric 版本化（§6）+ 补标子集消化，**9/18 gold 定稿前完成**即可。
- **B/C 排期挤**：标注单个场景约几十秒，57 个 ≈ 1–1.5 小时/人（分三天各 ~20 条），量级可控；若实在来不及，允许只标自己段内且两人重叠的子集（如共同 S001–S030）——收缩方案由 A 在 9/11 前拍板，不要私自缩。

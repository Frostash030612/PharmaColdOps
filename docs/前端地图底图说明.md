# 地图底图（basemap）：为什么图是灰的，以及怎么彻底解决

## 现象

地图只显示路线、站点与图例，底图是灰的，下面一行提示 **"Basemap unavailable. Actual road routes remain visible."**

## 原因

底图不是本地数据，而是浏览器向 **OpenStreetMap 官方瓦片服务**发的网络请求：

- 修改前：`frontend-vue/src/components/LeafletMap.vue:385` → `https://tile.openstreetmap.org/{z}/{x}/{y}.png`
- `tileerror` 一旦触发，`tileError` 置真，模板渲染上面那句提示（`LeafletMap.vue:440` 附近）

所以灰底图的三种常见触发条件：**断网 / 代理或校园网拦截 tile.openstreetmap.org / 触发 OSM 限流或封锁**。注意地图上**真正要展示的东西全部是本地数据**（`src/data/singaporeRoutes.json` 的 19 个节点＋路线 GeoJSON，由后端按案例求解后返回），所以底图缺失时其实是一次**优雅降级**：路线仍可读，只是没有街道背景。

## 为什么不能长期依赖 OSM 官方瓦片

OSM 的 Tile Usage Policy 只允许**轻量、交互式**使用，明确禁止大流量、批量抓取与"绕过缓存"的用法，并可能对**滥用来源直接封锁**（返回 403/429）。一个反复起停服务、来回截图、还要现场演示的原型，正好落在会被限流的模式里——**演示当天被封锁就等于图变灰**。

## 解决方案：把演示区域的瓦片预取到本地（已实现）

1. **预取脚本**：`scripts/fetch_map_tiles.mjs`
   - 从 `singaporeRoutes.json` 自动推出演示区域的经纬度包围盒（19 个节点），按 `z10..z14` 逐级算瓦片编号，只下载需要的那些（当前约 **183 张、~2 MB**），带 User-Agent 标识、串行限速（并发 4）、失败重试 3 次、已缓存跳过。
   - 输出到 `frontend-vue/public/tiles/{z}/{x}/{y}.png`。Vite 会把 `public/` 原样拷进构建产物，dev 与 build 都能用。
   - 用法（**需要一次联网**）：
     ```powershell
     node scripts/fetch_map_tiles.mjs                 # 默认 z10..z14
     node scripts/fetch_map_tiles.mjs --zoom 10 15    # 想更清楚就加一级（瓦片数约 ×4）
     node scripts/fetch_map_tiles.mjs --dry-run       # 只列出会下载哪些
     ```
   - 路网以后扩到包围盒之外（例如新增设施）时**重跑一次**即可。

2. **前端改为「本地优先、在线兜底」**：`LeafletMap.vue` 的底图现在是
   - 默认用 `./tiles/{z}/{x}/{y}.png`（本地，零外部请求，断网也能显示）；
   - 本地瓦片缺失时自动回落一次在线 OSM 图层；
   - 两者都失败才显示那句 "Basemap unavailable"，并保留路线；
   - 需要在线底图时可显式指定：`?tiles=osm`。

3. **顺序很重要**：改完前端要**重启 dev server**（Vite 对 `public/` 的新增文件不会热更进已运行的服务），或者重新 `build`。

## 演示与截图建议

- 想拿到带街道底图的截图：先跑预取脚本 → 重启 dev server → 重新截图。之后底图**不依赖网络**，评审现场断网也不怕。
- 来不及预取也行：确认这台机器能访问 `tile.openstreetmap.org`（浏览器直接打开 `https://tile.openstreetmap.org/10/806/507.png` 能看到方块图），进页面后**等 1–2 秒**让瓦片加载完再截。
- 如果就用灰底图那张，也说得过去：把提示读作「底图不可用但路线仍可见」，正好体现降级能力——但不要让它变成对网络状况的现场赌博。

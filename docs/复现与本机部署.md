```bash
python3.12 -m venv .venv
```

## 2. 完整本机部署

需要Docker Engine／Desktop和支持 `up --wait` 的Compose插件，首次构建需要访问镜像、PyPI和npm仓库。
镜像构建与节点选取遵循 [Docker多阶段构建](https://docs.docker.com/build/building/multi-stage/)，
启动以 [Compose健康依赖](https://docs.docker.com/compose/how-tos/startup-order/) 等待图谱真正就绪。
前端按 [pnpm冻结锁](https://pnpm.io/cli/install) 构建后由
[FastAPI StaticFiles](https://fastapi.tiangolo.com/tutorial/static-files/) 同源提供。

```bash
# 在仓库根目录；生成随机私有密码，不覆盖已有配置，不打印密码。
.venv/bin/python scripts/configure_demo.py
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml config --quiet
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml up -d --build --wait --wait-timeout 180
```

打开 `http://127.0.0.1:8080/`。若端口占用，首次配置时加 `--port 8081`，或自行调整已有私有env的端口。
已存在 `deploy/demo.env` 时配置器拒绝覆盖，不随重跑旋转密码。不要把配置或完整 `docker compose config`／inspect输出发到Git。

新项目名 `pharmacoldops-demo` 与旧 `pharmacoldops` 分离；三个具名卷独立保存audit数据库／JSONL、图谱数据和日志。
不挂载宿主 `data/audit` 或现有模型，不启动旧 `pharmacoldops-neo4j-1`。
Neo4j不向宿主公开7474／7687，API只绑定127.0.0.1；应用以UID10001、只读rootfs运行，可写仅audit卷与临时目录。
API单worker，避免SQLite、模拟时钟和进程锁的多进程歧义，不声明横向扩容已验证。

前端镜像默认 `same-origin`，无需手填API地址；`/?api=` 显式进入离线模式，保留原独立静态前端默认离线行为。
`/?api=http://...` 仍可指定其他API。离线不能登记、调度或访问真实KG／M4。
运行模式下订单仍模拟，不要求具体货量／仓库余量；五仓库允许停车选择和医院禁止日终停车保持不变。
没有把地图在线瓦片当本机离线资产：镜像不包含被git忽略的缓存瓦片，无网络时可退化到路线视图。

## 3. 初始化、就绪与升级

首次启动只给**空图谱**加载规则、证据、设施路网和8000条基准运输记录，再写入种子指纹。
非空图谱必须带本部署匹配的指纹；未知／版本改变时启动失败，绝不自动清空历史。
兼容重启不重新训练模型、不重建图谱；自动审计并重放缺失且不冲突的案例链，冲突要求人工处理。
升级涉及规则／静态图谱变化，应先备份，建立新项目和卷，演练迁移再切换，不覆盖旧卷或绕过指纹。

| 检查 | 意义 |
|---|---|
| `/api/health` | 规则服务进程存活，不代表图谱／存储／模型全部可用 |
| `/api/ready` | 本部署SQL只读连接／完整性、两个模型校验、图谱产品依赖；缺失返回503 |
| `/api/graph-sync` | SQL记录对应的图谱队列状态；synced不等于后续永不丢边 |
| check_case_graph.py | 对照原SQL／JSONL检查实际案例链，可显式修复缺失、不冲突部分 |

图谱中断时SQL登记仍保存，KG问答503、就绪503；重启后自动outbox补偿。
就绪接口不泄露连接串／密码，不写案例，不代表登录控制、临床有效性或整体生产认证。
若需要独立前后端部署，可配置CORS_ORIGINS逗号列表；本方案空列表，同源无需开放跨域。
CORS不是认证：无登录／角色权限的原型不得直接当公网多用户系统发布。

```bash
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml ps
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml logs --tail 80 api
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml restart api
# 停止但保留全部数据卷；不要加 -v。
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml down
```

## 5. 停写备份与新实例恢复

SQLite是案例／配送状态权威，图谱是可重建镜像。快照不包含密码或模型；同时保留对应应用镜像ID、
代码版本和配置指纹，不能在任意新模型／规则版本上自动接受旧案例。
必须先停止API：SQLite backup API提供DB一致快照，但不保证活跃写入时与JSONL的一致时间点。
`--quiesced` 是操作人的确认，不是脚本能认证的停写证明；不能用在线目录copy代替停写流程。

下面用专用具名备份卷，避开桌面目录共享；若改用宿主bind目录，需要先确认Docker文件共享权限。
备份工具使用非交互one-off root只为读取卷／写快照，实际API仍非root；不要向API上传或自动加载外部pickle。

```bash
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml stop api
docker volume create pharmacoldops-demo-backups
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml run -T --interactive=false --rm --no-deps --user 0:0 \
  --entrypoint python -v pharmacoldops-demo-backups:/backups api scripts/runtime_snapshot.py backup \
  --source /runtime/audit --output /backups/demo-snapshot-NEW --quiesced
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml up -d --no-build --wait

# 必须使用全新项目名，不能覆盖已有演示卷。
.venv/bin/python scripts/configure_demo.py --output deploy/restored.env --port 8081
docker compose --env-file deploy/restored.env -p pharmacoldops-demo-restored -f deploy/compose.demo.yml \
  run -T --interactive=false --rm --no-deps --user 0:0 --entrypoint python -v pharmacoldops-demo-backups:/backups \
  api scripts/runtime_snapshot.py restore --snapshot /backups/demo-snapshot-NEW --target /runtime/audit
# 使用同一新env与project，避免与原8080端口冲突。
docker compose --env-file deploy/restored.env -p pharmacoldops-demo-restored -f deploy/compose.demo.yml \
  up -d --no-build --wait --wait-timeout 180
```

新项目每次命令须用同一私有env、project名和端口；如新图谱尚未启动，可为其生成新的独立密码。
恢复拒绝非空目标、哈希不一致、目录穿越或符号链接；不对原部署做删除或替换。
恢复文件归属目标卷用户，避免root恢复后非root API无法写入。
SHA-256用于完整性检查，不是数字签名；只恢复可信备份。故意篡改manifest不能由单纯哈希鉴权。
图谱中的额外人工／非权威数据不在此SQL重建方案内；如添加这类数据，应另做Neo4j原生停库备份。

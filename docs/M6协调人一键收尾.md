更新：2026-10-23。本次A/B已回收并按[描述性评审](M6评审收尾.md)完成归档。描述性复算使用`scripts/summarize_m6_review.py`及本次私有过程记录；独立指标保持不可用。

下述第1–5节保留原独立双人协议的操作流程，不是本次收尾状态。`finalize_m6_review.py`的独立性、历史时序和仲裁校验保持不变，不应为取得分数而补造确认。
当前修复不能覆盖正在评审的2026-10-03冻结回答；本工具只给那一批出结果。

## 1 核对材料

已有文件：`data/qa/m6-completed-20261016-intent-A.csv`、`data/qa/m6-completed-20261016-ratings-A.csv`。
B交回自己的intent-B.csv、ratings-B.csv；保持53题、包／响应SHA、同人两阶段ID，不查看A原标签或系统预测来填。
两份意图都应在系统回答发放前封存，评审本人实际查阅来源，记录真实提交／封存时间。
如历史记录缺失或阶段顺序不成立，保留未核实状态并说明局限，不能编造时间、补签身份或自动认定严格独立。

先运行材料核验（缺B时返回非零，输出清单和空过程模板，这是正常的待完成状态）：

```bash
.venv/bin/python scripts/finalize_m6_review.py --output data/processed/m6-final-check-new
```

本命令不启动Docker、图谱、在线问答，也不读取新版本答案给旧批评分。
模板中的真人／独立性／查阅确认默认null，时间默认空白，工具没有替真人声明。

## 2 收齐B后生成分歧清单与过程模板

替换为实际回收位置。输出目录必须是新目录，不覆盖旧审核记录。

```bash
.venv/bin/python scripts/finalize_m6_review.py \
  --intent-b /absolute/private-review/intent-B.csv \
  --ratings-b /absolute/private-review/ratings-B.csv \
  --output data/processed/m6-final-with-B-new
```

如果A文件也放在其他位置，另传`--intent-a`和`--ratings-a`。输出：

- `status.json`：缺失／已校验输入、意图分歧数量；未完成时human_metrics为null。
- `process-record-template.json`：已有文件SHA与评审ID由工具读取；真人声明、实际时间由协调人与本人核对后填写。
- `intent-disagreements.csv`：只有问题及A/B判断／理由，不包含系统预测。
- `adjudication-template.csv`：仅列分歧题，最终标签、仲裁人和理由保持空白，交不同的第三人填写。

双方意图相同且acceptable_intents的原字符串相同才算一致。集合顺序不同也会进入分歧；保留原件并交C说明，不偷偷改评审意见。
答案／证据的0–2序数评分不做强制合并，保留分歧和各自分母。

## 3 填写真正的过程记录

复制第2步生成的过程模板，填写协调人ID、两位真人ID、human_confirmed、independent_intent_confirmed、sources_consulted_confirmed。
所有确认必须是真正核对后填true。ID须对应CSV，同一人不能换名双评。

填写`intent_sealed_at`、`answers_disclosed_at`、`ratings_submitted_at`的真实ISO时间并带时区，
例如格式为`YYYY-MM-DDTHH:MM:SS+08:00`。必须是两份意图都先封存，再发回答，之后才提交评分。
不清楚实际时间时保留待确认；来源URL后来替换的题，要由本人确认确实读过替换后的资料。
文件SHA需与封存副本一致；修订过的文件必须另外记录版本与封存情况，不能沿用旧SHA装成原件。

本工具只验证自报过程是否内部一致，不能认证真人身份、真实时间或专业资质。

## 4 正式评分并更新报告源稿

无分歧时省略adjudication；有分歧时必须传C填写的文件。下例展示有分歧情况：

```bash
.venv/bin/python scripts/finalize_m6_review.py \
  --intent-b /absolute/private-review/intent-B.csv \
  --ratings-b /absolute/private-review/ratings-B.csv \
  --process-record /absolute/private-review/process-record.json \
  --adjudication /absolute/private-review/adjudication.csv \
  --update-docs \
  --output data/processed/m6-human-final-new
```

只有完整标注、过程核验和必要仲裁都通过，才调用原评分器并生成`report.json`、`report-section.md`。
其中保留准确率／macro-F1／κ、歧义分母、双人正确性2比例、逐评分项的分母／NA与文件SHA。
`--update-docs`只替换M6报告和英文组报告中的指定汇总区，不删除历史回收说明，不改原标注、冻结包或其他文字。
校验缺失／失败时不会把公开报告改成完成，也不会产生正式分数。

Windows使用`.\.venv\Scripts\python.exe`，把上述命令写成一行，不照抄Bash行末反斜杠。
依赖使用项目`requirements-eval.lock.txt`；格式检查可先跑`check_m6_annotation.py`。

# M6问答修复与新版本验收

2026-10-17。A对冻结v1回答的评分暴露了明确的回答边界问题，本轮按这些失败修复当前实现。
这是开发回归与软件验收，不是新一轮独立人工评估；原53题、回答、A标注和逻辑指纹保持不变。

## 已定位的问题

| 旧行为 | 修复后的行为 |
|---|---|
| 天气／实际效价问题掉入“每个回答都有法规依据”的通用宣传文字 | 明确拒答并列出支持范围，不查询图谱 |
| FAQ称超出稳定性边界就必须报废、复验确认效价 | 标明只是概念和原型规则，真实产品结论需要适用证据与质量授权 |
| 宽泛substring先匹配，who代词可误匹配WHO，threshold可误匹配hold | 英文按词边界匹配、区分WHO缩写，复合／不明确任务要求澄清 |
| 含“为什么”的原因背景问题抢先落到处置原因 | 按明确任务短语识别，支持五个显式查询入口 |
| 后端不可用时将通用概念当作案例回答 | 显示查询不可用，不沿用旧证据或自动补成FAQ |
| 切换案例、产品、语言或修改问题时旧请求可能晚到 | 清空旧回答与证据，以请求身份丢弃过期回包 |
| 图谱引用只显示编号，HTTP响应模型丢弃新增来源字段 | 保留可选来源URL、历史核对说明和适用范围，通过响应模型传到界面 |
| 产品存在但没有法规边时被当作不存在 | 返回insufficient_evidence；不存在才返回no_case |

A的部分评分看似矛盾（例如对“必须报废”给正确性2又标unsupported_claims=1），这仍是评审原记录，
不修改分值来迎合修复。B和必要仲裁完成后才生成正式双人结果。

## 当前用户操作

问答区新增查询类型：原判定依据、审计链、当前产品工程配置、已记录原因背景、全部图谱案例处置统计。
旁边显示当前归档案例与产品。查询不会从问句自动切换案例ID或产品；需要先在界面打开相应记录，再查询。
问句出现其他规范案例ID、已知产品ID或有限产品别名时要求澄清；全量统计不偷偷按句中产品筛选。它不是通用实体识别。
自动识别只处理有限中英文短语，不是LLM理解。未识别或多个任务同时命中时使用澄清提示／显式选项。
概念回答始终标明未查图谱；结构化查询需要在线服务，案例类还需要当前归档ID。

Regulation／SOP条目显示存储的原则摘要，可由用户点击打开来源并展开历史核对记录。
链接只允许无凭据的http(s)协议。来源记录、一般原则和当前产品可接受偏差不是同一证据层次。
页面不自动下载外站、认证来源是否当前有效，或把核对日期升级为临床／监管认证。

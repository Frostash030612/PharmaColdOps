# M6 独立人工评估交接指南

交接日期：2026-10-04。对象：接手评估的组员／协调人，以及两位人工评审。

## 1. 这次需要完成什么

M6 是系统的知识图谱问答模块。本次不是开发新功能、训练模型或重新测试配送，而是请真人独立判断：

- 用户的问题属于哪一种问答任务？系统是否识别正确？
- 系统给出的回答是否正确、是否真正回答了问题？
- 引用的证据是否相关、充分？该拒答的时候是否合理拒答？

工具和冻结评审包已经准备好，目前缺的是人工标注、人工评分和必要的分歧仲裁。
**完成标注前，独立准确率是“不可用”，不是 0，也不是 100%。不能让 AI 代填、让程序预测充当人工标准，或一人换两个名字做双评。**

接手人先做三件事：领取现有评审包；确定评审 A、B 和备用仲裁人 C；按下面顺序分发材料。
本文第 2–5 节可作为评审说明；第 6–9 节供协调人使用。意图标签封存前，不向评审开放整个仓库、系统回答或私人预测材料。

## 2. 人员分工与材料分发

| 角色 | 要做什么 | 限制 |
|---|---|---|
| 协调人／接手组员 | 保管评审包、分阶段分发、回收封存、汇总分歧、运行评分、写报告 | 不替评审填答案，不按系统预测修改人工标签 |
| 人工评审 A | 独立完成 53 条意图标签，再独立完成 53 条答案／证据评分 | 两阶段使用同一个真实评审 ID |
| 人工评审 B | 同上，与 A 独立完成 | 必须是另一个真人，不看 A 的标签或评分 |
| 仲裁人 C | 如有意图分歧，给出最终单标签及理由 | 必须不同于 A、B；不能直接抄系统预测 |

协调人可以兼任评审，但只有在尚未查看预测、路由关键词和系统回答、能够保持阶段顺序时才适合参与。
已熟悉对应问句路由实现的人不应充当盲评者。记录评审背景和利益关系，不能仅凭自报 ID 宣称专业独立认证。

第一阶段分别发给 A、B：`questions.csv`、各自的 `intent-A.csv` 或 `intent-B.csv`，以及本文第 2–5 节／包内 `INSTRUCTIONS.md`。
**不要发 `answer-review/`、`reference-sources.json`、`predictions.private.json`、代码、测试答案或对方的文件。**

收齐并封存两份意图标签后，第二阶段才发 `responses.json`、`reference-sources.json`，以及各自的 `ratings-A.csv` 或 `ratings-B.csv`。
两位评审仍独立评分，评分提交前不讨论具体题目。私人预测文件始终由协调人保管，不是评审材料。

## 3. 第一阶段：独立填写意图标签

每人处理全部 53 条，不删除难题或只挑容易的题。按问题想完成的任务判断，不按某个关键词机械匹配。

| `expected_intent` 的合法值 | 含义 |
|---|---|
| `why_disposition` | 某个具体案例为什么被这样处置，以及相应依据 |
| `audit_chain` | 某个案例的异常、决策、补发等全过程审计链 |
| `product_requirements` | 产品储存温度、允许偏离时长等要求 |
| `cause_context` | 某个案例记录的原因通常关联哪些运输阶段／产品等背景模式 |
| `disposition_stats` | 已登记案例的处置数量／分布统计 |
| `unsupported` | 不属于上述任务，如天气查询或要求证明具体品牌药品真实临床效价 |
| `ambiguous` | 问句确实无法唯一确定任务；必须附可接受标签集合 |

不存在的案例不等于超范围：如果问的是案例处置原因，仍按该任务标注；系统是否合理报告“没有该案例”，在第二阶段判断。
孤立词语可能有歧义，不要为凑齐单标签强行判断。

`intent-A.csv`／`intent-B.csv` 的填写规则：

- 保留 `question_id`、`question`、`lang`、`packet_sha256` 和原有表头，不能改写问题或哈希。
- `annotator_id`：每一行填写自己的同一固定 ID，例如 `reviewer_A`；B 必须使用不同 ID。
- `expected_intent`：填上表中的一个精确英文值，不写中文释义或多个标签。
- `acceptable_intents`：普通单标签留空；`ambiguous` 时用英文分号连接合法任务标签，如 `why_disposition;audit_chain`，分号两侧不要加空格。不包含 `ambiguous` 自身。
- `note`：建议写判断理由；歧义题应说明为什么有多种合理解释。

保存为 UTF-8 CSV，使用编辑器时避免改坏长哈希、引号、逗号或多行文本。检查导出后仍是 53 条数据行。
提交后，协调人保留只读原件并记录提交时间；若后续更正，另存版本并注明原因，不根据系统表现倒改标签。

## 4. 第二阶段：独立审阅答案和证据

用 `question_id` 对照 `responses.json`，查看原问句、`response`、`case_facts`、证据及响应哈希。
**评估的是这一版冻结回答，不是今天在线页面的新回答；无需自己创建案例、登记订单或重跑服务。**

不要把回答中的处置结论或 `case_facts` 的自动规则结果直接视为领域真理。核对问题、案例事实和参考来源是否真正支持该回答；
对阈值，要区分项目工程默认配置与法规／制造商稳定性证据。

| CSV 字段 | 合法值与判定原则 |
|---|---|
| `answer_correctness` | `0`：错误／未回答任务；`1`：部分正确、有实质遗漏；`2`：在原型范围内正确且充分回应 |
| `evidence_relevance` | `0`：证据无关；`1`：部分相关；`2`：直接相关；不需要证据时可用 `NA` 并解释 |
| `evidence_sufficiency` | `0`：证据不支持结论；`1`：仅支持一部分；`2`：足以支持所作结论；不需要证据时可用 `NA` 并解释 |
| `refusal_appropriate` | `0`：拒答／无法作答处理不当；`1`：合理；不涉及此项填 `NA` |
| `unsupported_claims` | `0`：未发现无依据的实质性断言；`1`：发现了，请在 `note` 说明 |

`answer_correctness` 和 `unsupported_claims` 不允许 `NA`。所有评分必填，不能用空白、`N/A`、小数或文字替代。
`unsupported_claims` 与其他项方向不同：**1 代表存在问题，不代表表现好**。

其他字段：

- `annotator_id`：必须与本人第一阶段 ID 一致；A、B 不可互换。
- `packet_sha256`、`response_sha256`、`question_id`：保持原样。
- `relevant_evidence_ids`：记录实际相关的证据 ID，多个建议用英文分号分隔；无相关证据可以留空，但在 `note` 解释。
- `checked_source_urls`：每行记录自己真正查阅的来源 URL，多个建议用英文分号分隔。该字段不能空，也不能填虚构网址、`NA` 或“已经检查”。
- `note`：记录扣分理由、证据不适用原因，以及来源名称、章节／页码或可核对的原文位置。

仅有官方链接不等于该链接支持具体稳定性数值。依据来自工程配置时明确说明，不能把配置升级成真实产品效价保证。
没有证据要求的超范围问题，也需记录实际用于判断系统边界的来源；必要时由协调人在第二阶段提供可访问的项目范围文档链接。
若无法实际查阅来源，先向协调人报告并补齐查阅条件，不造一个 URL 通过检查。脚本只验证字段存在，不验证网址内容或是否真的看过。

## 5. 分歧处理与个人交回清单

A 交回 `intent-A.csv`、`ratings-A.csv`；B 交回 `intent-B.csv`、`ratings-B.csv`。各文件完整保留 53 行。
不需要两人把答案评分改成一致：评分差异本身就是报告内容。

协调人对照意图标签和 `acceptable_intents`，整理所有不一致的 QID；即使两人都写 `ambiguous`，可接受集合不同也算分歧。
交给 C 的材料应包含问题、标签定义、双方标签与理由，但不包含系统预测。C 填写 `adjudication-template.csv`：

- 对每个分歧 QID 填 `adjudicator_id`、`expected_intent`、`note`，保留原包哈希。
- 最终标签只能是六个任务标签之一，不能填 `ambiguous`；C 的 ID 必须不同于 A、B。
- 不能裁定时，保持未完成并说明原因，不强造结论。当前评分工具不会给未完成仲裁的包出正式分数。
- 双方一致标为 `ambiguous` 且可接受集合一致的题，不需仲裁；正式报告会单独列出歧义排除数，不纳入单标签准确率分母。

完成后，保留两人的原始意见；仲裁结果另存，不覆盖 A、B 的文件。

## 7. 协调人：回收后生成正式评分

以下命令在仓库根目录执行，假定四份已完成 CSV 位于下面路径。
若使用私有回收目录，将对应参数改为回收文件路径；不要为套用命令而覆盖原空白模板。
使用项目现有 `.venv`，或按复现文档安装 `requirements-eval.lock.txt`。
**对现有包执行 `score` 不调用在线服务／图谱，不需要重新跑 `prepare`。**

没有意图分歧时：

```bash
.venv/bin/python scripts/evaluate_m6_independent.py score \
  --packet data/processed/m6-blind-20261003-v3/predictions.private.json \
  --intent-a data/processed/m6-blind-20261003-v3/blind-intent/intent-A.csv \
  --intent-b data/processed/m6-blind-20261003-v3/blind-intent/intent-B.csv \
  --ratings-a data/processed/m6-blind-20261003-v3/answer-review/ratings-A.csv \
  --ratings-b data/processed/m6-blind-20261003-v3/answer-review/ratings-B.csv \
  --output data/processed/m6-human-score-handoff-new
```

有分歧时，在同一条命令中增加：

```text
--adjudication data/processed/m6-blind-20261003-v3/adjudication-template.csv
```

只传已填写完整的仲裁文件。输出目录必须不存在；首次成功后要另起新目录重跑，不能删除原始报告或覆盖历史结果。
成功产物为输出目录中的 `report.json`。常见拒绝原因：

| 报错关键词 | 需要检查 |
|---|---|
| `unlabelled` / `invalid human quality rating` | 标签／评分为空、值不合法，或误写 `N/A` |
| `all packet rows` / `duplicate annotation` | 缺题、重复 QID 或混入别的批次 |
| `different response packet` / `response content changed` | CSV 指纹被编辑，或题目与回答来自不同包 |
| `reviewers must differ` / `phase reviewer identities` | 同人双评，或两阶段 ID 不一致 |
| `provenance missing` | 未记录实际查阅来源 |
| `require human adjudication` / `not all disagreements` | 存在未完成的意图分歧仲裁 |
| `fresh output required` | 输出目录已存在，应另起版本目录 |

错误不能通过伪造 ID、随便补 URL、抄系统预测或删题解决。检查实际数据；无法解决时记录阻碍，暂不宣称完成。

## 8. 协调人：写入报告并交回成果

评分成功后，更新 [M6 独立评估](M6独立评估.md) 和项目 `PROGRESS.md`，至少包含：

1. 本批指纹、评审人数／身份背景、盲评与封存时间、仲裁过程，以及匿名 ID 与真实参与人之间的私有记录。
2. 题数、六类意图准确率／macro-F1／混淆矩阵、各类支持数、歧义排除数与实际分母。
3. 人工间 Cohen’s κ、意图分歧和仲裁理由。κ 反映评审一致性，不是系统准确率。
4. 各评审正确性／证据相关性／充分性／拒答／无依据断言的分数与分母、`NA` 数和配对一致率。
5. `independent_answer_adequacy_rate_both_raters`：**两人均给正确性 2 分的答案比例**，不是简单平均分，也不是临床准确率。
6. 失败案例、原因分析、改进建议与局限；不要只展示高分或隐去难题。

该语料是 37 条既有 FAQ 关键词加 16 条开发者编写问句，共 53 条，不是自然采样的真实用户语料。
本批含实际服务回答与前端概念回退；既有 466 项派生契约检查不是人工准确率，来源链接也不是独立领域有效性证明。
若后续修复问答或增加题目，应另开评估版本，保留本批的冻结结果，不回写旧回答使成绩变好。

需要交回：四份完整 CSV；有分歧时的仲裁 CSV；机器评分 `report.json`；评审与封存记录；正式报告文档更新；未能核实的来源／问题清单。
评分工具只能核对结构和自报身份，不能证明真人参与、专业资质、真实查阅或独立性，协调人负责如实记录这些过程。

## 1. 这个系统是做什么的

冷链药品（疫苗、生物制品）在运输或仓储中一旦发生**温度偏移**（偏热或偏冷），质量负责人必须判断这批货该怎么办。现实中最常见的问题不是"没有监测"，而是**监测报警之后没有一条可追溯的判断链**：温度曲线有了，但"凭什么判它报废"、"依据哪条法规"、"剩下的货怎么补送"散在邮件、表格和几个人的经验里。

PharmaColdOps 把这一串接成一个闭环：

```
温度偏移事件
   ↓
① 处置建议    放行 / 复检 / 报废 + 规则路径 + 法规依据
   ↓
② 人工审核    边界情况强制转人工，人工结论覆盖自动建议（原始记录保留）
   ↓
③ 补发改派    生成补发需求 → 在主线上比较"改这辆车的路线 / 另派一辆 / 返仓取货"
   ↓
④ 地图与审计  在地图上看改道前后对比；导出可打印的审计报告
   ↓
⑤ 追问依据    "为什么这样处置？" → 知识图谱给出法规与 SOP
```

它覆盖课程要求的四类智能推理技术：**决策自动化**（规则引擎）、**知识发现与数据挖掘**（温度/MKT、风险与根因模型）、**资源优化**（VRPTW 车辆路径）、**认知系统**（知识图谱问答）。

## 2. 5 分钟把它跑起来

### 方式 A：Docker 一键起（推荐，评审用这个）

**前提**：装了 Docker Desktop，并处于 **Linux 容器模式**；端口 8080 没被占用。

在仓库根目录依次执行三条命令：

```bash
# ① 生成随机密码与私有配置（不会覆盖已有配置，不会打印密码）
.venv/bin/python scripts/configure_demo.py

# ② 校验配置能解析
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml config --quiet

# ③ 构建并启动，等到全部就绪
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml up -d --build --wait --wait-timeout 180
```

> **Windows 用户**把 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。
> 如果还没建过 `.venv`，先看第 8 节。

**然后打开浏览器**：

### 👉 http://127.0.0.1:8080/?lang=zh

看到界面就成功了。首次启动会自动给空图谱加载规则、法规、设施路网和基准运输记录——**第一次可能要等一两分钟**，属正常。

**验证是否真的健康**（可选）：

| 地址 | 说明 |
|---|---|
| `http://127.0.0.1:8080/api/health` | 进程存活 |
| `http://127.0.0.1:8080/api/ready` | **更严格**：数据库、两个模型、图谱依赖都就绪才返回正常 |

**用完关掉**（保留数据）：

```bash
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml down
```

> ⚠️ **不要加 `-v`**，那会删掉数据卷。

## 3. 完整演示走查（照着点即可）

下面这条路径是**被设计过的最短闭环**，按顺序点即可。界面为中文（`?lang=zh`）。

### 第 0 步：认识三个区域

打开页面后，界面大致分三块：

- **左侧**：事件/案例列表与登记入口
- **中间**：地图（配送路线与车辆）
- **右侧**：处置、审核、审计等操作面板

### 第 1 步：建立"今天的主线"（配送计划）

在配送面板点：

> **🎲 生成今日批次（按日期）**

系统会生成一批模拟订单并给出**预览**（里程、车辆数、要服务的设施、站序）。确认后：

> **确认发车**

现在地图上出现了一辆车按固定站序在跑——这就是**主线**。

> 💡 **为什么要先做这步？** 支线（异常改派）**只能挂到当天正在进行的主线上**。
> 如果你先结案再建计划，系统会明确拒绝并提示你先生成批次——这是**故意的护栏**，不是故障。

### 第 2 步：制造一个温度偏移事件

在左侧登记一个事件，或从已有事件列表中选一个**会判报废**的案例（例如 `R01`）。

关键点：**选与当前批次相同产品的案例**（演示批次常用 `vaccine_2_8`）。
不同产品的余货不能互相顶替，这是设计。

### 第 3 步：结案，并立刻看处置方案

点：

> **结案并查看处置方案**

这一步会同时给你两样东西：

1. **处置建议**：放行 / 复检 / 报废，**附带规则路径与法规依据**（哪条规则命中、引用哪份 WHO/EU GDP/ICH 依据）
2. **改派方案对比表**：系统比较几种候选做法：

| 候选 | 含义 |
|---|---|
| 在途车用**车上余货**顺路加一站 | 不回仓库，最快，但要求同产品同温区 |
| **另派一辆备用车** | 备用车从仓库出发 |
| **返仓取货** | 先回仓库再送 |

表格会显示每个方案**多跑多少公里、ETA、会影响哪些订单（含因此变迟的）**。

> 地图上同时出现支线标记：**红点**＝受影响的医院，**红虚线圈**＝支线新站点。

### 第 4 步：看"改道前后"的对比

点：

> **⛶ 展开地图**

进入大图运输视图，这里有：

- **灰虚线** ＝ 改道**前**要走的路线
- **红实线** ＝ 改道**后**实际走的路线
- 已送达的站＝灰色 **✓**、未送达＝带站序号

还可以：**调整倍速**、**⏸ 暂停**（真正的时钟冻结，不是停止刷新）、**跟随车辆**。

### 第 5 步：采用一个方案

在对比表里选定一行，点：

> **采用此方案**

方案立即写进正在跑的作业。若采用"车上余货"，你会看到车上余货减少、而仓库批次没动。

### 第 6 步：追问"凭什么"

用知识图谱问答问，例如：

- "这个案例为什么判报废？"
- "这批货的储存条件要求是什么？"

答案会带**法规与 SOP 出处**；如果系统没有证据，它会**明确说没有**，而不是编一个答案。

### 第 7 步：导出审计报告

在案例详情导出**可打印的 HTML 报告**与**完整 JSON 快照**（含原始自动建议、人工结论、配送状态与图谱覆盖情况）。

### 演示中常见的"看起来像故障"其实都是设计

| 你看到的 | 其实是 |
|---|---|
| 没建计划就结案 → 被拒绝并提示 | 护栏：支线必须挂到主线 |
| 换了别的冷藏产品，余货方案不出现 | 余货是 `vaccine_2_8`，不同产品不能顶替 |
| 某些事件不做自动处置，要求人工审核 | 边界/低置信情况**强制转人工**，是安全设计 |
| 时钟自己停了 | 有订单待审核时演示时钟会暂停（面板会说明） |

## 4. 界面上每一块是干什么的

| 区域 / 按钮 | 作用 |
|---|---|
| **🎲 生成今日批次（按日期）** | 生成模拟订单批次并预览；确认后建立当天配送作业 |
| **确认发车** | 让车队按时钟出发 |
| **⏮ 重演这一批 / 重演上一次作业** | 用同一批订单重新跑一遍（旧作业留作历史）；刷新页面后也能用 |
| **结案并查看处置方案** | 结案 + 立刻列出全部改派候选，**选定才写进作业** |
| **🔍 预览处置方案 / 对比并选择处置方案** | 只读预览：在你采用之前不占用库存或车辆 |
| **采用此方案** | 把选定候选提交进正在跑的作业 |
| **⛶ 展开地图** | 大图运输视图：时钟、倍速、暂停、跟随、对比开关、车辆列表（`Esc` 关闭） |
| **主动申请人工审核** | 把当前事件提请人工判定；审核前不能补发、标为已处理或结案 |
| **次日 / 跨天** | 收工停车（仅限五个仓库节点，医院不能日终停车），并建立次日固定计划 |
| **导出审计报告** | 可打印 HTML + 完整 JSON 快照 |

**地图图例**：灰虚线＝改道前／已走过；实色加粗＝剩余路线；站点上的数字＝站序；红点＝受影响医院。

## 5. 没有后端时怎么办（离线模式）

前端有**内置的离线规则引擎**，没有后端也能演示处置判断：

在地址栏把 `?api=` 留空即可，例如：

```
http://127.0.0.1:8080/?api=          ← 显式进入离线模式
```

**离线模式能做**：规则处置判断与界面浏览。
**离线模式不能做**：登记案例、调度配送、访问真实知识图谱与模型。

> 演示时如果网络或后端挂了，可以退到离线模式继续讲规则部分；但要**说明**这是离线兜底，不是真实后端结果。

## 6. 出问题了怎么排查

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 打不开 8080 | `docker compose ps` 看容器状态；`/api/ready` 返回 503 说明依赖未就绪，看 `docker compose logs api` |
| 端口被占用 | 首次配置时加 `--port 8081` 重新生成配置；或改 `deploy/demo.env` 里的端口 |
| 首次启动很慢 | 正常——首次要给空图谱加载数据，等 1–2 分钟 |
| 页面显示 "Knowledge graph unavailable" | 图谱没起或未连上；处置功能仍可用，但问答会退化为离线提示 |
| 地图只有路线没有底图 | 离线瓦片未缓存且无网络，退化为路线视图；连网或用 `?tiles=osm` |
| 改了后端代码但行为没变 | **后端不会自动重载**，必须重启 uvicorn。演示前踩过的坑 |
| 想换中文/英文 | 地址栏 `?lang=zh` 或 `?lang=en` |

### 有用的命令

```bash
# 看服务状态
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml ps

# 看 API 日志
docker compose --env-file deploy/demo.env -f deploy/compose.demo.yml logs -f api

# 看就绪状态（503 = 有依赖没准备好）
curl http://127.0.0.1:8080/api/ready
```

### ⚠️ 一个重要提醒（给在本机 Windows 上跑测试的人）

本机**中文 Windows** 上跑全量 `pytest` 会看到大量失败，**那不是代码坏了**：
`src/optimisation/case_action_guard.py` 使用了 Unix 专有的 `fcntl` 文件锁，并且**有意在非 Unix 平台
fail closed**。团队的完整测试基线（见 `PROGRESS.md`）是在 **Linux 容器**里取得的。
判断代码是否健康，请用 Docker 的 Linux 环境，不要以 Windows 本机的红灯为准。

## 7. 这个系统不做什么（重要）

评审与使用者都应知道这些边界，**它们不是缺陷，是如实披露的范围**：

| 边界 | 说明 |
|---|---|
| **数据是模拟的** | 温度序列、订单、货量均为**模拟数据**；风险模型训练数据来自公开数据集且**很可能是合成的**。系统不产生真实药品处置授权 |
| **不是生产部署** | 仅绑定 `127.0.0.1`，**无用户认证**，未做公网安全加固，不是生产/合规系统 |
| **不替代药师判断** | 规则阈值是**工程假设**（原则锚定默认值），不是产品级稳定性结论；法规引用停在文档级，ICH 部分到条款级 |
| **人工审核是强制的** | 边界与低置信情况必须人工确认；人工结论单独保存，原始自动建议不被覆盖 |
| **标注一致性未达标** | 双人标注 Cohen's κ = **0.6434**，低于原定 0.80 目标——**如实报告，未通过重测修饰** |
| **M6 人工评测尚未完成** | 冻结输入与离线填写工具已就绪，但**截至 2026-10-12 尚无真人标注**，独立准确率暂不可用 |
| **ML 不进在线决策** | M4 模型分数作为**辅助信息**进报告，不驱动报废/放行；前端风险指数仍是规则启发式 |
| **优化器有边界** | 求解器是 OR-Tools Routing Solver + GLS（**不是 CP-SAT**），限时结果不保证全局最优，重跑可能不同 |

完整的不确定性披露见 [`PROGRESS.md`](../PROGRESS.md) 与各模块文档。

## 8. 给技术人员的附录

### 开发模式启动（不用 Docker）

```bash
# 后端（仓库根目录）
# macOS / Linux
.venv/bin/python -m uvicorn --app-dir src api.main:app --port 8000
# Windows PowerShell
.venv\Scripts\python.exe -m uvicorn --app-dir src api.main:app --port 8000

# 前端（另开一个终端）
cd frontend-vue
pnpm install --frozen-lockfile
pnpm dev
# 后端模式：http://localhost:5173/?api=http://127.0.0.1:8000&lang=zh
```

### 从零建立环境

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-eval.lock.txt
.venv/bin/python -m pip check
npm install --global pnpm@12.4.1
pnpm --dir frontend-vue install --frozen-lockfile
pnpm --dir frontend-vue build
```

**锁定基线**：Python 3.12.12｜Node 24.15.0｜pnpm 12.4.1。
`requirements.txt` 是更宽的研究环境，**不是**演示安装器。

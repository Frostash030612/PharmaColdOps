## 1. 30 秒看懂现状

demo 现在有**两种运行模式**：

| 模式 | 怎么开 | 判定是谁算的 |
|---|---|---|
| **离线**（默认，旧行为） | `frontend/index.html` 直接打开 | 页面内置的 JS 移植引擎（结果与 Python 引擎一致） |
| **API / 全后端**（本轮新增） | URL 加 `?api=http://127.0.0.1:8000` | **Python 后端 = 真规则引擎** `src/rule_engine/`，前端只负责显示 |

一句话分界：**后端判「语义」（放行/复验/隔离/报废、命中第几条规则、证据分级、风险原因代码），前端管「文案」（把语义代码翻译成中文或英文）。**

## 3. 后端用了什么

| 技术 | 作用 | 说明 |
|---|---|---|
| **Python 3.12**（仓库 `.venv`） | 运行环境 | 项目其余模块（ML / 规则引擎）同环境 |
| **FastAPI** | Web 框架 | 自动生成交互式 API 文档：起后端后浏览器开 `http://127.0.0.1:8000/docs` |
| **Uvicorn** | ASGI 服务器 | 让 FastAPI 跑起来的那条命令 |
| **Pydantic v2** | 请求/响应校验 | 类型不符自动返回 422（如未知产品 id） |
| **真规则引擎** `src/rule_engine/` | 判定 | API 只是它的薄封装，不是重写 |
| **pytest + TestClient** | 契约测试 | `tests/test_api_contract.py` 8 条 |

> ✅ **环境**：`fastapi` / `uvicorn` 已在 `requirements.txt` 的 **M7 API/前端** 节（组员 cdd6e7b 补齐）。新 clone 的机器 `pip install -r requirements.txt` 即含这两个包；旧 `.venv` 若还没装，单独 `.venv/Scripts/python.exe -m pip install fastapi uvicorn` 一次即可。

## 4. 前端用了什么

| 技术 | 作用 |
|---|---|
| **原生 HTML + CSS + JS（ES6）** | 页面本体——**零框架、零构建、零 node 依赖**，双击 `index.html` 都能跑（`file://`） |
| [frontend/real_data.js](../frontend/real_data.js) | 场景与地图数据 |
| `fetch()` + `URLSearchParams` | 读 `?api=` 参数并发 POST 请求 |
| 本地化文本表 `RULE_TEXT` / `CAUSE_TEXT` / `EV_LBL` | 中英文案各自一套；按后端返回的 `rule_no` / `cause_code` / 证据等级查表翻译 |
| 模块级 `view` 状态 + 指纹比对 + 序列防抖 | 只在需要时向后端要数、避免乱序覆盖 |

**前端自己不判任何东西。** API 模式下连热力图、预置卡片颜色都来自后端；后端不可达时自动切回内置 JS 引擎兜底（页面顶部有状态小圆片：`已连接 Python 引擎 / 不可达·本地兑底 / 连接中`）。

## 5. 怎么跑、怎么连

### 5.1 起后端（终端 1，仓库根目录）

```bash
# 首次需先装（见第 3 节注意）
.venv/Scripts/python.exe -m pip install fastapi uvicorn

# 起服务
.venv/Scripts/python.exe -m uvicorn --app-dir src api.main:app --port 8000 --log-level info
```

### 5.2 起前端静态页（终端 2）

```bash
python -m http.server 5500 -d frontend
```

### 5.3 打开

- 离线模式（行为同旧版）：`http://127.0.0.1:5500/index.html`
- **API 模式（判定走后端）**：`http://127.0.0.1:5500/index.html?api=http://127.0.0.1:8000`
- 中文版：`index-zh.html` 同样加 `?api=…`

连接就是「**浏览器用 fetch 向 Uvicorn 发 HTTP/JSON**」，跨域由后端 CORS 全开解决（所以从 `file://` 直开也能连）。

### 5.4 四个真请求长什么样

```
浏览器  ?api=http://127.0.0.1:8000
 │  fetch POST /api/decide
 │  { product_id, excursion_temp_c, duration_min, mkt_c,
 │    packaging, stage, spec_override? }
 ▼
Uvicorn(8000) → main.py → service.py
 │  resolve_spec(): 合并沙箱 override → 单产品副本 RuleEngine
 ▼
rule_engine/engine.py evaluate() ← rules_config.json（行为源）
 │  Decision{disposition, rule_no, reason, reshipment_required}
 ▼
返回 JSON（语义，不含任何中文/英文文案）
前端按 rule_no / cause_code 查本地文本表 → 显示
```

| 方法 路径 | 何时调用（前端） | 请求要点 | 响应要点 |
|---|---|---|---|
| `GET /api/health` | 页面加载时探测后端在不在 | 无 | `{status, products}` |
| `POST /api/decide` | 拖滑杆 / 换产品 / 随机事件（**防抖 ~80ms + 指纹防乱序**，每次只发当前一条） | `EventIn` + 可选 `spec_override` | 完整判定 dict（见下） |
| `POST /api/decide_batch` | 页面启动**一次**（18 张预置卡片上色） | `{events:[EventIn…]}` | `{decisions:[{disposition, rule_no, reshipment_required}]}` |
| `POST /api/grid` | **换产品 / 改 spec 时一次**（不是每个格子一次请求） | `durations`(升序) + `mkts`(降序, 顶行最高) + 事件基础 | `{rows: disposition 二维矩阵}`，`rows[0]` = MKT 最高行 |
| `POST /api/route` `/api/qa` | 暂未接（C 模块上线后启用） | — | **501** 占位 |

`/api/decide` 真实请求与返回（`curl` 直接可复现）：

```bash
curl -X POST http://127.0.0.1:8000/api/decide \
  -H "Content-Type: application/json" \
  -d '{"product_id":"vaccine_2_8","excursion_temp_c":20.0,"duration_min":90,
       "mkt_c":19.0,"packaging":"intact","stage":"transit"}'
```

```json
{
  "disposition": "scrap",
  "rule_no": 3,
  "reason": "excursion severity beyond any acceptable margin",
  "regulation": "WHO TRS 961 Annex 9 — excursion beyond acceptable stability margin",
  "reshipment_required": true,
  "rule_path": "vaccine_2_8 (2–8 °C) at 20 °C for 90 min (MKT 19 °C, allowable 30 min) → scrap: excursion severity beyond any acceptable margin",
  "event": {"product_id": "vaccine_2_8", "excursion_temp_c": 20.0, "duration_min": 90, "mkt_c": 19.0, "packaging": "intact", "stage": "transit", "spec_override": null},
  "spec": {"product_id": "vaccine_2_8", "storage_min_c": 2.0, "storage_max_c": 8.0, "allowable_duration_min": 30, "mkt_threshold_c": 10.0, "retestable": true, "freeze_sensitive": true},
  "evidence": {"packaging": "ok", "temp": "breach", "freeze": "ok", "duration": "severe", "mkt": "severe"},
  "risk": {"score": 99, "cause_code": "overtemp"}
}
```

字段速查：

- `disposition` ∈ `release / retest / quarantine / scrap`；`rule_no` 1–6（判定的「哪条规则」，**文案表用它**）；`reshipment_required = (scrap 或 quarantine)`。
- `evidence` 逐项 `ok / near / breach / severe` = 前端「为什么这么判」的状态章。
- `risk.score` 3–99 整数，`risk.cause_code` ∈ `frozen / packaging / overtemp / duration / mkt / near / inband / minor`（**文案表用它**）。
- 未知 `product_id` → HTTP **422**，detail 附合法 id 列表。

## 6. 怎么「看见」它在工作（录屏/演示必备）

### 6.1 前端一改，后端立刻响应 —— 看后端控制台

后端加了 **audit 日志**（[src/api/service.py](../src/api/service.py) 的 `_audit`）。API 模式下每动一次滑杆，后端控制台追加：

```
INFO:     [audit] decide vaccine_2_8 20°C/90min MKT 19°C intact/transit spec A=30min T=10°C retest=True → scrap (rule 3)
INFO:     127.0.0.1:5001 - "POST /api/decide HTTP/1.1" 200 OK
```

上行 = 审计（收到什么参数 + 按哪条 spec 判成什么），下行 = Uvicorn 访问日志。两行叠一起 = 「往返真实发生」的证据。改左栏沙箱阈值再拖 → `spec A=… T=…` 跟着变，说明前端发的 override 真的打进了引擎。

### 6.2 后端停了，前端自己兜底 —— 证明判定源在后端

Ctrl+C 停掉 uvicorn → 再操作前端 → 控制台不再有任何请求，顶部小圆片变「不可达 · 本地兑底」，页面照常可用 → 说明连上时判定**只**在后端。

### 6.3 从后端「控制」前端结果 —— 改行为源

判定行为唯一来源是 [rules_config.json](../src/rule_engine/rules_config.json)：把 `vaccine_2_8` 的 `allowable_duration_min` 从 `30` 改成 `90`（或阈值 `10.0→12.0`），保存重启 uvicorn → 同一事件与整张热力图都变，**HTML/JS 一行不用动**。演示完记得改回来（gold 场景测试依赖默认值）。

> 提示：`°` / `→` 在部分 Windows 控制台显示为 `��` 只是编码问题（cp936），换 Windows Terminal 或先 `chcp 65001`。

## 8. 设计约定（答辩口径，别破坏）

1. **后端判语义、前端管文案**。Python 里不出现中/英文案，原因：ZH 的 reason/法规/cause 是中文、EN 是英文，硬塞进 Python 会让后端背两套语言、改一句文案要重启服务。所以后端回 `rule_no`/`cause_code`/`evidence` 等级，前端 `RULE_TEXT`/`CAUSE_TEXT`/`EV_LBL` 查表。
2. **默认阈值永远以 `rules_config.json` 为准**。demo 左栏「规则配置沙箱」是演示可配置性，作为 `spec_override` **随每个请求显式上传**；服务端按「单产品副本引擎」合并，绝不改动模块级默认 specs。
3. **离线与 API 两种模式结果必须一致**（都来自同一套判定语义）。新增判定逻辑时，Python 引擎、JS 移植（`evaluate`）、契约测试要一起动。
4. 每个 `/api/decide` 都打一行 audit —— 这是演示「真后端在算」的现成素材。

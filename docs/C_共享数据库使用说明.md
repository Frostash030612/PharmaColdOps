# C 模块共享数据库使用说明

## 现在数据库在哪里

- 没有配置 `DATABASE_URL` 时，后端使用本机 `data/audit/dispatch.sqlite3`。它只用于离线开发和自动测试，不会提交到 Git，队友也不会共享这份数据。
- 配置 `DATABASE_URL` 后，后端使用云 PostgreSQL。所有连接到这套后端的成员看到同一批调度单、车辆进度和交付状态。
- Neo4j 仍负责知识图谱；PostgreSQL 负责会变化的业务状态。两者用途不同。

## 团队怎么使用

1. 团队在托管 PostgreSQL 服务创建一个数据库，开启 TLS，并保存平台给出的连接串。
2. 管理员通过安全渠道向需要运行后端的开发者提供连接串。不要把密码发到群公告或提交到 Git。
3. 每位后端开发者复制 `.env.example` 为 `.env`，把 `DATABASE_URL` 改成真实连接串。
4. 安装依赖后，仅由一人首次执行：

   ```bash
   python scripts/init_dispatch_db.py
   ```

5. 正常启动 API。后端读取 `DATABASE_URL`；前端继续请求 `/api/dispatch/*`，无需知道数据库账号。

部署到云服务器时，把同一连接串配置为服务端 Secret/环境变量 `DATABASE_URL`。浏览器不能直接连接数据库，生产环境只开放 API。

## 已实现的数据与并发保护

表 `dispatch_runs` 保存已接受的路线方案、原始订单/库存/车辆输入、执行状态和版本号。发车和逐站交付采用版本条件更新；两个人同时修改同一调度单时，后提交的一方会收到冲突，不会静默覆盖先提交的数据。

仓库不包含真实云连接串，因此当前提交完成代码和建表准备，不能替团队创建某个平台账号下的数据库实例。拿到连接串后执行初始化脚本即可接通。

# 异常登记幂等与离线规则沙箱

## 异常登记

`POST /api/case_close` 保留旧名称，但含义是登记并归档质控判定，不等于配送处置已经结案。
新增可选 `registration_id`：正常前端为每份新草稿生成独立 ID。
同一 ID、同一请求重试返回同一案例；同 ID 改事件、规则覆盖、开始时间或备注返回 409。
不同 ID 可登记内容完全相同的两次事件，不能用内容相同来错误合并真实的模拟事件。
旧客户端不传 ID 时，每次仍是新登记；要获得网络重试保护必须保留并复用客户端 ID。

新登记的权威存储为 SQLite／PostgreSQL 的 `case_registrations` 表，唯一约束处理跨线程／进程并发，
存储请求指纹及首次成功的完整判定。重试先读原记录，不重新绑定订单或重跑变化后的规则。
数据库不可用返回 503，不把“没有保存”报告为登记成功。
JSONL 保留作兼容镜像，Neo4j 保持 best-effort；镜像失败不丢失数据库登记。
历史查询合并数据库与旧 JSONL 并按案例 ID 去重；坏镜像行跳过且不删除原文件。
图谱不提供 exactly-once 保证，后续连通验收仍需检查镜像覆盖。

## 前端重试草稿

新增登记表单及原沙箱“登记后查看方案”共用登记控制器：第一次请求前固定 ID、开始时间和完整输入。
双击共用同一个在途请求；网络异常／503 后保留草稿，输入锁定，明确重试原登记。
草稿按后端地址保存于浏览器 sessionStorage，刷新或关闭弹窗再打开仍恢复原 ID 与输入，不自动提交。
成功响应后清除重试草稿；明确 422 校验拒绝允许修改输入后再登记。
无法使用浏览器存储时提示不要刷新，当前页面仍保留原 ID。

“放弃本地重试草稿”需确认：原请求可能已成功，应先查看过往记录。
放弃只清除本地草稿，不删除后台案例；之后新建草稿就是另一次独立事件。
已归档案例显示保存的判定快照，不因后台规则更新自动换判定；处理进度与备注仍由当前工作流返回。

## 离线规则沙箱

顶部“离线规则沙箱”不依赖后端可用性。没有 `?api=` 也可打开预设、时间线、温度／MKT 参数、规则配置、
边界图、证据和规则启发式风险；均为本地预览，不是临床稳定性验证或部署的 ML 推理。

在线模式也能进入本地实验，入口会保存进入前的案例、参数和本地审计行。
本地预览期间不发起判定、矩阵、登记、路线或调度命令，不提供处置采用／登记按钮，关闭后恢复原上下文。
在线作业的后台时钟不被改写；页面暂停额外的业务轮询，退出后恢复读取原作业进度。
不得把本地实验结果当成已经归档的案例或已执行配送方案。

## 验证

`tests/test_case_registration.py` 覆盖并发、相同事件不同身份、规则变化、提交前／提交后故障、
日志和图谱不可达；`scripts/test-registration.mjs` 验证冻结请求、session 草稿和来源隔离。
浏览器验收模拟成功提交后丢失响应，并在刷新后重试同一 ID；另检查离线入口无需后端、
本地修改不产生额外 API 业务请求、退出恢复原案例。

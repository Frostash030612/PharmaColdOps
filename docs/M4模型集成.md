# M4 风险与候选原因模型集成

## 当前定位

M4 已有离线训练实验；本轮新增可保存／加载的模型产物、只读推理 API、双语输入面板和随异常登记保存的首次评估快照。
规则 M3 仍是放行／复检／报废、补发和配送约束的唯一来源；旧启发式风险指数和图谱 Cause 不被 ML 覆盖。
模型超过分类阈值不等于报废，低于阈值也不等于药品安全。没有采集真实传感器、ERP、GPS 或仓库库存。

| 模型 | 训练目标与输入 | 不代表什么 |
|---|---|---|
| risk | `silent_failure`：运输天数、开门、温度／湿度摘要、缺测、振动及路段数，共 13 特征 | 非药品效价／报废标签，非产品专属稳定性验证，非未来 30／60 分钟预警 |
| cause | `excursion_cause`：设备、电源、监测及疫苗类别等设施月度上下文，15 特征／10 类 | 非本次事件已确认原因；特征关联不证明因果 |

风险数据疑似合成、原因数据明确为仿真。概率为分类器未经校准的输出，不是已校准的真实业务风险率。
风险模型不使用匿名 `feature_x*`、承运商／区域 ID，也不使用订单货量、仓库余额等演示版不关注的量货字段。
前端温度事件、MKT 与订单没有这些摘要／月度特征，**不自动映射、不补零捏造、不把天数改成分钟**。

## 训练与启动

```bash
.venv/bin/python scripts/train_m4_models.py
.venv/bin/python -m uvicorn --app-dir src api.main:app --port 8000
```

默认新建 `data/processed/m4/{risk,cause}/model.joblib` 和 `metadata.json`，另存 `training-report.json`；均为可再生成产物，不入 Git。
旧输出目录拒绝覆盖；重训用 `--output /absolute/new-model-directory`，然后将 `ML_MODEL_DIR` 配为该目录。
同一 Python／依赖环境训练和服务加载。未训练、缺文件、哈希不匹配或 scikit-learn 版本不兼容时明确 unavailable／503，
不会在请求中临时训练，不生成假分数，也不阻止未选择 M4 的原规则接口运行。
不接受上传 pickle／模型文件；仅加载服务器管理员指定、由本地训练生成的可信产物，不能把外部未知 joblib 放进该路径。

候选为 LogisticRegression 和 HistGradientBoosting，风险任务还在环境可用时比较 LightGBM／XGBoost。
本机两个原生库因缺 OpenMP 无法加载，报告真实记录 unavailable，而非伪称它们完成当前部署训练。
本轮实际部署的两类模型均由验证集选出的 HistGradientBoosting 提供；不修改全局 OpenMP 环境。

70／15／15 分层随机切分，填补、类别编码和缩放仅拟合训练集；风险以验证 PR-AUC、原因以验证 macro-F1 选模型，
风险分类阈值仅在验证集选 F1，选择完才计算留出集指标。原模型报告仍保留为历史实验，不能混写成新部署结果。
保存数据 SHA-256、分区 SHA、seed、特征顺序、算法、依赖版本、模型 SHA、阈值和测试指标。
缺少时间切分／设施分组验证，正式多折实验仍是后续任务。

本机新产物基准：risk F1 **0.6950**、ROC-AUC **0.9208**、PR-AUC **0.7264**；cause macro-F1 **0.1402**、
top-1 **0.1795**、top-3 **0.4850**。候选原因性能弱，UI 明确提示，只作为实验关联列表，不宣传成实用诊断。

## API

- `GET /api/ml/models`：两任务的 ready／unavailable、输入字段、模型标识、阈值与基准指标。
- `GET /api/ml/samples/{risk|cause}`：留出集的完整、支持范围内演示样本；不返回目标标签。
- `POST /api/ml/predict`：`task + source + sample_id + features`，只读，不登记／发车／改库存。
- `DecideIn`／`CaseCloseIn` 可带 `ml_contexts`（每任务最多一份），明确由操作员提供模拟上下文；无字段的老客户端完全兼容。

所有训练特征都须完整提供，拒绝目标列、多余列、布尔冒充计数、非有限值和明显不一致的温湿度摘要。
`dataset_sample` 的身份及特征必须与该模型留出样本一致，手工改值应改为 `manual_simulated`，不能伪称采集数据。
超出训练数值范围或未知类别时返回 out_of_domain，不外推出一个风险概率；超低温摘要不能伪装成该运输基准内的有效预测。

推理结果标 advisory_only、数据来源及模型 ID。解释是“把单个特征替换为训练参考值时概率如何变化”，
名为 reference-replacement sensitivity，**不是 SHAP、不保证可加和、不是根因因果证据**；离线旧 SHAP 图仍为独立实验产物。

## 前端及登记

在线点击 `+`，新登记表单中打开 M4 风险／候选原因两页：加载演示样本或填写完整输入 → 调用训练模型 →
可显式勾选“将此模拟上下文随新登记保存”。基准样本不是此订单读数，勾选表示人为指定的演示上下文。
编辑任何输入即作废旧预测和该任务的选中上下文；切换任务可分别保存风险与原因两份输入。
没有货量／库存输入，不自动从 MKT 或现有订单填造字段。

首次登记保存 `ml_contexts`／`ml_assessments` 的模型 SHA、输入、来源、概率／候选和解释；草稿重试身份指纹包含上下文。
同身份修改上下文返回 409；成功后，即使模型丢失或更换，也返回原快照，不重算历史。
旧案例无 M4 快照时明确显示未保存，不伪补预测。在线模型故障、输入无效或样本冒名不会被保存为成功评估。
离线规则沙箱不加载模型、不调用 ML API、不用启发式分数冒充 ML，进入／退出仍保持原案例上下文。

## 验收

`tests/test_m4_integration.py` 用独立模型和临时存储检查真实推理、输入／样本拒绝、域外不外推、规则不变、归档不重算、
模型缺失／校验失败及只读无业务写入；`scripts/test-ml.mjs` 检查零值、输入键、深复制及旧载荷兼容。
`scripts/browser_m4_acceptance.cjs` 用真实前端操作检查两模型、输入编辑失效、登记／刷新快照及离线零 ML 请求。
模型二进制与评测／浏览器输出不提交；克隆后请先运行训练命令。

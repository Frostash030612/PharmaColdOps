# 事件模型不确定性、拒判与人工审核门禁

2026-10-04，接续[事件模型基线](事件级模型基线评估.md)。
已完成独立门禁、默认关闭的shadow接口、案例审核衔接与新仿真批次验收。
**门禁功能已实现，但当前模型的候选质量没有达标：冻结策略拒绝支持唯一候选，全部转人工。**
这不是把误报降为0或准确率变成100%；旧风险／月度原因模型和当前运行演示服务没有切换。

## 1. 模型输出和执行权限分开

`src/ml/event_gate.py`只看33项公开观测特征和11项模型分数，不看隐藏机理、角色、ID或歧义标签。
门禁顺序如下；原因可以同时出现，并非只保留一个：

| 情况 | 行为 |
|---|---|
| 输入含隐藏字段、非法数值／区间或伪造采样节奏 | 拒绝输入，接口422 |
| bundle未配置、损坏、版本／契约不符、预测异常 | 明确unavailable，仍必须人工审核；不退回旧模型猜原因 |
| 特征缺测、超训练范围、温度／辅助覆盖不足80%、前缀不足60分钟 | abstained，保留证据不足原因 |
| 未知扰动分数≥0.2、原始候选为空、多个候选、分数低或差距小 | abstained；空候选绝不表示安全 |
| 门、设定点、热缓冲和人员语义可能共用机理 | 扩展相关候选，并拒绝唯一语义归因 |
| 验证侧筛选条件没有合格方案 | validation_screen_not_qualified，拒绝支持全部唯一候选 |
| 所有筛选条件通过（单元测试覆盖此路径） | 仅candidate_only，仍review_required=true、禁止自动动作 |

人员开门／设定点／热缓冲子型与其他工程机理共用观测；候选包含门／温控／热缓冲时加入人员操作可能，
人员候选出现则扩展这三种工程可能。该保守语义规则不是从私有歧义flag读出来的，也不是人员责任认定。
原始候选、扩展候选、未校准分数、拒判原因、缺测／越界字段分开保存。
训练min/max包络仅是工程边界检查，不保证检出所有分布外输入；80%／60分钟／0.2等是固定演示策略，不是药品临床阈值。

## 2. 验证选择，不能为了覆盖率放宽质量门槛

继续使用已冻结的完整HGB，模型SHA不变：
`d44915bc1150938c3983055548777e64a0fc2a249a9adcd39dfecdfa9d56c8bd`。
只从旧train拟合公开特征包络；只在旧validation的600事件选择筛选参数。
不重新训练模型，不用旧四种测试成绩选择门禁，也不使用新批次标签选策略。

固定10组合：分数下限0.70／0.80／0.90／0.95／0.99，第一／第二分数差≥0.20／0.40。
只有同时满足**至少30个支持事件、完整机理集合精确率≥90%、无注入故障的受支持误报≤5%**才可选；
合格时先最大覆盖，再精确率、较高分数／差距；没有合格组合则enabled=false。
这些是工程资源分配条件，不是统计证明、医学认证或部署授权。

| 分数下限 | 验证支持数（差距0.20／0.40） | 候选完整集合精确率 | 无注入故障受支持误报 |
|---|---|---|---|
| 0.70 | 89／88 | 84.27%／84.09% | 0/92 |
| 0.80 | 84／84 | 84.52%／84.52% | 0/92 |
| 0.90 | 72／72 | 83.33%／83.33% | 0/92 |
| 0.95 | 62／62 | 82.26%／82.26% | 0/92 |
| 0.99 | 35／35 | 85.71%／85.71% | 0/92 |

没有一个达到90%：提高分数没有持续提高精确率，**高模型分数不能当成校准后的正确概率**。
验证侧0.99／0.40诊断的5个错误中，3个仅抓到多故障中的一个（燃料＋人员、热缓冲＋延误、热缓冲＋气流），
另外2个把主电源中断判成备用燃料不足。这是验证侧错误核查，不据此改阈值、隐藏机理或新批次标签。
多故障遗漏不通过“删去次要机理”修正，门禁不是要求每个真实发生的隐藏机理一定可从当前前缀识别。

最终策略保留最严格0.99／0.40参数但**enabled=false**；支持候选数0、精确率null（不是1），全部需审核。
旧验证已被之前实验检查过，验证搜索精确率不是未见数据估计。

## 3. 冻结后生成的新批次

CLI先写protocol、选门禁、保存bundle与冻结选择，再调用未修改的v1生成器：seed=20261004、6,000事件。
新数据train3000／validation600**未用于拟合或选择**，只评分四种test角色，共2,400事件。
全6,000事件／特征／标签／索引检查通过，12次重放、12次未来机理前缀不变、336对观测等价对通过。
与旧6,000事件相比，家庭、虚拟设备和精确特征画像重叠均0；不重采样来隐藏重叠或失败。

换seed也改变虚拟设备：新基础32台和新留出8台均未在旧训练出现。
因此新 `test_iid` 是“nominal参数＋新基础设备”，**不是相同设备纯IID**；
`test_facility`是另一组新设备，`test_scenario`仍是未见激励＋新设备，参数角色是压力参数＋新设备。
物理／噪声假设仍来自同一未标定模拟器；不存在独立真实业务验证或真正未见原因类别验证。

全部转人工代表审核负担100%，不是可规模化自动诊断方案。

## 4. shadow接口与现有人工审核链路

新增 `POST /api/ml/event/assess`，请求只有 `{"observation": <公开观测>}`。
只读预览不训练、不登记案例；不接受客户端scores、label、review_required、model_path或bundle上传。
API检查有限时间／数量、逐区间采样节奏和观测白名单，非法NaN／Inf以422返回，不回显完整错误观测导致500。

新增可选 `event_context={"observation":...}`，可提交给 `/api/decide` 和 `/api/case_close`：

1. 观测产品必须匹配案例，必须附完整M2 `temperature_context`，时间／温度／来源／EA与观测生成的温度证据一致。
2. 若选择一个超限窗口，原M2窗口核验和M3规则照常进行；整段观察可无假造温度／MKT标量，仅操作扣留。
3. 保存公开观测、门禁结果、模型／策略／观测／特征哈希；注册摘要包含全部观测，换辅助通道也不能冒用旧登记ID。
4. 服务层强制review_required，候选不改写M3原始处置／风险／补发结论；包括模型未配置或筛选通过两种情况。
5. 复用现有审核投影：待审时effective_disposition=null，补发、处理／结案、关联原订单送达／提速受阻。
6. 人工审核写入独立历史及有效处置，release可恢复配送，scrap按原补发链路执行；幂等、版本冲突和执行后锁定规则仍有效。
7. 登记重试返回原冻结快照，不因模型更新再次评估；审计JSON保存完整来源，HTML摘要不重复大段原始通道日志。

这只是自报模拟观测与案例的**一致性**，不验证实车传感器真实性、订单物理来源或审核人真实身份。
人工记录仍是demo自报身份；不能将人工处置结论自动当成已确认的故障原因标签或医学gold。
未提交event_context的旧案例契约／登记指纹保持不变，不能宣称系统所有旧来源都已切换事件模型门禁。

默认没有 `EVENT_GATE_DIR`，不扫描／自动采用实验模型，不替换原 `ML_MODEL_DIR`。
管理员未来若授权shadow试用，应显式配置可信本地bundle目录；只读取其hash校验、版本／特征契约一致的本地模型。
哈希不是数字签名或防恶意管理员认证，不能装载用户上传的joblib。
本轮**没有配置生产／演示env、重建演示镜像、启用新模型，也没有提供前端事件采集入口**；
现有人工审核界面／链路可处理已登记的待审案例，专属事件输入界面与正式演示接入仍是后续工作。

## 6. 下一步建议

门禁保持，先改善**多故障遗漏与电源／备用燃料区分**，以及压力环境／缺测的泛化；
若建设v2数据和时序模型，须新版本提前声明训练混合覆盖、保留不可辨识／弱可见事件、重新冻结独立批次。
不回改v1、不删次要机理、不降低90%门槛来制造本轮“合格”，也不把当前零支持包装成高准确。
在候选质量达标及明确授权后，再讨论事件模型专属前端、shadow试用与演示接入。

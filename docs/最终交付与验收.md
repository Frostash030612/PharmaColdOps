## 复建报告

文档构建额外需要`python-docx`；PDF附录合并需要`pypdf`，不属于运行服务的依赖。
使用安装了这些文档依赖的Python运行：

```bash
python scripts/build_final_report.py --output /absolute/new-directory/PharmaColdOps-Group-Report.docx
```

用Word／项目文档渲染流程导出并检查所有页后，再把渲染出的正文PDF与原proposal合并：

```bash
python scripts/build_final_report.py --merge-pdf /absolute/new-directory/rendered-report.pdf --output /absolute/new-directory/PharmaColdOps-Group-Report.pdf
```

两个输出都要求新文件，不能覆盖组员人工改过的Word或旧报告。修订正文后需重导出、重验版式和重做PDF合并。

## 检查与打包

以下检查只列出必需文件是否存在，不生成ZIP，也不将缺失视频标为完成：

```bash
.venv/bin/python scripts/package_submission.py --check
```

视频准备好并完成组内终审、保存所有改动为commit后执行。将`--name`改为实际日期／班级／组号要求，
下面只是Project Group 41的示例，不替代Canvas命名要求：

```bash
.venv/bin/python scripts/package_submission.py \
  --promotion /absolute/private-delivery/promotion.mp4 \
  --system /absolute/private-delivery/system.mp4 \
  --name IRS-PM-2026-10-25-GRP-41-PharmaColdOps \
  --output /absolute/private-delivery/IRS-PM-2026-10-25-GRP-41-PharmaColdOps.zip
```

ZIP包含成员信息、两个独立视频、组报告、对应commit的源码ZIP及文件SHA清单。
工具拒绝缺文件、覆盖旧包、未提交工作区、危险文件名和误跟踪的运行／密钥文件。
它不证明视频可播放、真人发声、恰好5分钟、评审独立性或Canvas已提交；这些由团队验收。

# 模拟订单生成器（v1）

项目使用模拟业务数据，不要求接入医院真实订单。设施名称、道路及供货点目录来自仓库已有数据；
订单、数量、库存、车队、收货／营业窗口和截止时间均为演示假设，不能据此声称已经验证真实配送效果。

## 使用方式

API 模式的配送面板上选择场景、配送日期、随机种子和订单数，点击“生成模拟订单并预览”。
查看全部配送组、未服务原因及“查看原始订单”，可下载包含完整输入与复现参数的 JSON。
只有规划可行且生成参数未变更时才能确认作业。生成与预览均只读，确认才预留库存并建立作业。
旧版固定演示仍可从场景选择进入；高级一键快捷方式也明确保留为旧版，不使用新场景参数。

## 场景与默认参数

| 场景 | 药品／货源 | 每单数量（箱） | 普通时间窗跨度（分钟） | 可用车辆 |
|---|---|---|---|---|
| `routine` 普通配送 | 全目录药品，主仓 | 5–25 | 180–300 | 6 |
| `urgent` 紧截止 | 冷藏药品，主仓；第一单带紧截止标记 | 5–20 | 180–300 | 3 |
| `multi_source` 多货源 | 全目录，优先合法分拨点 | 5–25 | 180–300 | 6 |
| `capacity_shortage` 运力不足 | 疫苗，主仓 | 55–75 | 240–360 | 1 |

新场景默认 8 单，每单一产品，每家医院一单；数量可配置为 2–14 单，但必须覆盖所选全部产品。
容量默认每车 100 箱，按每个随车品类 10 箱备用量占载重。生成足量的模拟批次库存（需求合计 × 1.2，向上取整），
不把“库存校验失败”混成“车队不足”。车辆规模是独立资源配置，不随需求量自动增长。

紧截止单的 `latest_min` 根据最早收货分钟 + 15 分钟准备 + 直接自由流行驶时间 + 额外余量构造，
额外余量默认 20 分钟，仍不超过医院收货窗。其余窗口在演示营业时段内变化。
这是**初始批次里的紧截止订单**，不是独立加急单或在途插单，后者仍是另一个待完成事项。

场景是参数预设，不是保证成功／失败的标签。自定义参数可能改变可行性；生成器从不调用规划器或反复重抽，
普通场景也可能在用户设置严格约束后无法完成，默认不足运力场景的未服务订单会被真实规划器保留。

## API 与复现

`POST /api/dispatch/simulated-orders`：

```json
{
  "scenario": "multi_source",
  "operating_date": "2026-10-01",
  "seed": 7,
  "order_count": 8
}
```

可选覆盖项：`product_ids`、`origin_facility_ids`、`quantity_min/max`、`window_min/max`、
`fleet_size`、`vehicle_capacity`、`spare_quantity`、`urgent_slack_min`。
省略药品／货源列表或留空的数值范围使用预设；显式空列表、未知品类、重复 ID、非法供货点、
货源无法供应产品、少于所需温区的车队、备用量不小于容量等请求返回 422。
未传日期按新加坡当天；未传种子按配送日期 YYYYMMDD。种子 0 与备用量 0 都是合法值。

响应包含 `note`、`metadata` 和可直接提交给 `/api/dispatch/plan`／`/runs` 的 `plan`。
`metadata` 保存生成器版本、完整有效配置 `config`、路网／目录／供货表的 SHA-256、批次 ID、紧截止订单 ID 和数据摘要。
同时记录生成器源码 SHA-256，避免同名版本在代码修改后误称为相同输入。
订单、批次、车辆编号包含配送日期与有效配置／源数据和生成器版本的指纹；同一批内唯一，跨日期与参数版本不串单。

把导出 JSON 中的 `metadata.config` 再提交给生成接口即可复现。
相同日期、种子、有效参数和源数据版本的订单、库存、车队和元数据完全一致。
文件指纹不同表示底层路网／目录版本已变，不能声称复现的是同一批次；生成器版本为 `simulated-orders-v1`。

确认作业后保留生成快照与指定配送日期。跨天沿用固定批次时更新实际作业日期，
但保持原始生成配置并注明 `carried_forward_to`，不冒充重新生成的订单；提供新的次日批次时日期须为父作业次日。

## 边界和验证

- 箱单位是标准化演示载重，不是实际重量、体积、车辆冷链认证或配载规则。
- 每医院一单；暂不模拟同医院多张非重叠时间窗订单、复杂多行采购单、效期／FEFO 或真实采购流程。
- 随车备用量是初始载货假设，仓库库存单独生成；不在运行中重置已有作业的库存。
- 无实时 GPS／拥堵、生产订单系统或隐藏的服务端自动排程。

代码：`src/optimisation/simulated_orders.py`；API：`SimulationBatchIn` 与 `simulated_plan_request`。
验证：`tests/test_simulated_orders.py`、旧 `tests/test_daily_orders.py`、`scripts/test-simulation.mjs`，
并与配送执行／跨天测试一起回归。前端真实浏览器验收使用隔离的临时库存与作业，不修改现有演示记录。

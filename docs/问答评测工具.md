# 问答评测工具：隔离运行与清理

`scripts/evaluate_qa.py` 检查 57 个场景的回答／原判定一致性、法规／SOP 引用、产品阈值、状态及跨案例证据隔离。
全量共 466 项派生检查。它不是独立医学有效性验证，也不测意图识别准确率；37 条意图问句仍待人工标注。

## 默认安全运行

```bash
.venv/bin/python scripts/evaluate_qa.py
.venv/bin/python scripts/evaluate_qa.py --limit 5
```

需要本地 Docker 和已安装的 Neo4j 5 镜像。默认复用 `neo4j:5-community` 的本地镜像，
若该 tag 不存在则只读取得项目已有 `pharmacoldops-neo4j-1` 的镜像 ID；不隐式下载镜像。
也可用 `--image` 指定已安装镜像。

每次创建自己的容器、固定空闲端口、独立 SQLite／JSONL，并仅在这份新空图谱中载入静态证据。
不会启动、停掉、清库或重建项目已有图谱，不使用 `DATABASE_URL` 指向的业务运行库写评测案例。
写入、API 服务查询和清理共用 `knowledge_graph.connect.get_driver`，不再写死另一套地址和认证。

每批案例有随机 `RQAEVAL-<批次 UUID>-` 身份和图谱 ID；清理只针对本批精确 ID：

- 图谱中的事件及补发单同事务清理。
- 独立 SQL 的登记、graph outbox、工作流同时清理，避免图谱删除后被补写任务重建。
- JSONL 删除本批记录，不留下“已归档但图谱已删”的孤立登记。
- 保留 `cases.manifest.json` 判定快照、报告和本地空存储供核对；不把 manifest 当业务归档。
- 清理出错返回失败，保留本地恢复来源，不冒充评测成功；图谱清理失败时不继续删 SQL 原始记录。
- 最后只移除自己成功创建的容器及匿名临时卷，不删共享 Disposition／Cause／法规／SOP 等节点。

默认报告位于新的临时评测目录 `report.json`，终端打印路径，不再覆盖旧 `data/processed/qa_eval_report.json`。
`--workdir` 指定的新目录必须不存在；`--report` 指定的报告文件也不能已存在。
返回码：0＝检查与清理通过；1＝检查不通过；2＝环境、运行或清理失败。失败检查数按实际执行次数记录，
异常时保留已创建案例与 manifest，不填造一个全量通过分母。

## 显式保留评测数据

```bash
.venv/bin/python scripts/evaluate_qa.py --keep --workdir /absolute/new-evaluation-directory
```

保留的是本批自己的图谱容器、独立登记／队列／归档，仍不写项目运行库。
报告给出容器 ID 和 Bolt 地址；临时图谱演示认证固定为 `neo4j / isolated-qa-demo`，仅用于本机独立容器。
检查完成后由操作员按该确切容器 ID 停止、移除，不对项目 compose 执行 `down -v`。

## 使用已有的专用测试图谱

```bash
NEO4J_URI=bolt://127.0.0.1:17689 NEO4J_PASSWORD=your-test-password \
  .venv/bin/python scripts/evaluate_qa.py --configured-test-graph --limit 5
```

只有显式加这个选项才使用 `NEO4J_* / .env / compose` 解析的图谱。此图谱须已初始化，**不能把业务图库当测试库**。
脚本不会重建它，仍强制用新的本地评测 SQLite／JSONL；仅精确删除本批案例，不删除其他案例或静态节点。
共享测试图谱的 Cause／Disposition 概念节点可能因案例写入而补齐，需完全无影响时使用默认自建模式。
不要给其他补写进程指向评测目录；本批不启动后台 worker，避免清理时与外部 worker 竞争。

## 文案一致性

mRNA 超低温演示类别的实际规则为 `−80…−60 °C`；EN／ZH 前端名称和供货目录名称均按此校准。
输入滑块的 `−90…0` 是实验可调范围，不是合法储存温区，未被收窄。
数值阈值、供货能力、真实运行快照和历史案例未改；目录文字变化会正常改变新模拟批次的目录来源哈希。
